Weak-constraint 4DVar

Strong-constraint 4DVar (chapter 6) treats the forward model as exact. For real systems this is wrong, as models have biases, missing physics and discretisation error. Over long assimilation windows the trajectory drifts away from the observations because the model itself is wrong, even when the analysis is good. Weak-constraint 4DVar admits this model error as an additional control variable.

Cost function¶

xt=Mtfree(xt−1)+ηt, with ηt∼N(0,Qt)x_t = M_t^\text{free}(x_{t-1}) + \eta_t, \text{ with } \eta_t \sim \mathcal{N}(0, Q_t)xt​=Mtfree​(xt−1​)+ηt​, with ηt​∼N(0,Qt​)

Why the model-error term matters¶

Two failure modes of strong-constraint 4DVar:

  • Climatological drift. The free model’s climatology differs from reality. Long windows produce xTx_TxT​ far from yTy_TyT​ regardless of x0x_0x0​, and the analysis tries to compensate by moving x0x_0x0​, which damages the early-time fit.

  • Missing fast physics. The model resolves the slow manifold but not the fast (cloud microphysics, sub-grid turbulence). Strong 4DVar attributes fast-physics errors to x0x_0x0​, which is the wrong place.

Allowing ηt\eta_tηt​ to absorb these errors per-step gives a better fit at every time without distorting x0x_0x0​.

Every site is observed at every time with R=0.01IR = 0.01 IR=0.01I; the background is xb=0x_b = 0xb​=0 with B=IB = IB=I, and the model-error covariance is Q=0.04IQ = 0.04 IQ=0.04I.

It prints x₀ error: strong 2.81, weak 0.25 and mean η* 0.46: the strong analysis moves x0x_0x0​ to make up for the missing forcing, while the weak analysis puts it into η\etaη.

The model error covariance QQQ is a separate input. Three common parameterisations:

  • Diagonal: lineax.DiagonalLinearOperator(variances), white Gaussian model noise. Simple but rarely realistic.

  • Matérn spatial: kernellib.ImplicitKernelOperator(matern, coords) with a Matérn kernel function, for spatially correlated model error.

  • Markovian time-correlated: Ornstein-Uhlenbeck QtQ_tQt​ with correlation timescale τ\tauτ. The error decorrelates over τ\tauτ steps, which is physically motivated.

The choice of QQQ is the single most important tuning choice in weak-constraint 4DVar. Too tight, and the result reverts to strong; too loose, and the observations dominate the analysis to the exclusion of the dynamics.

Computational cost¶

The control vector dimension grows with TTT:

dim⁡(control)=dim⁡(x0)+T⋅dim⁡(xt)\dim(\text{control}) = \dim(x_0) + T \cdot \dim(x_t)dim(control)=dim(x0​)+T⋅dim(xt​)
(7.3)

For T=100T = 100T=100 and a 2D field with n=104n = 10^4n=104, this is ∼106\sim 10^6∼106 control variables instead of 104. The minimisation is correspondingly heavier. Two mitigations:

  • Lower-rank model-error parameterisation. Restrict ηt\eta_tηt​ to a low-dimensional subspace (POD modes, learned latent space). vardax does not provide this out of the box; users supply a custom reparameterisation via an eqx.Module.

  • Shorter sub-windows. Run weak-constraint 4DVar over a short sub-window where ηt\eta_tηt​ dimensionality is manageable, cycle the result via pipekit_cycle.SmootherCycle. Operational ECMWF uses this pattern.

When WeakFourDVar is the right answer¶

Use WeakFourDVar for multi-time observations when the model is known to have biases (the two failure modes above), strong-constraint analyses misfit the later times of a long window, and you have a reasonable model-error covariance QtQ_tQt​ (often from comparing the free model to higher-fidelity runs or to reanalyses). If model error is small (within the observation noise), use StrongFourDVar (chapter 6), since the extra control variables are not worth the cost.

If you’d rather replace the parametric prior with a learned one, FourDVarNet (chapter 9) is the alternative. The learned prior absorbs the same kind of model error that ηt\eta_tηt​ would, without an explicit augmented control.
