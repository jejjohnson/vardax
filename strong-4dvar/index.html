Strong-constraint 4DVar

When observations are spread across an assimilation window and the state evolves through known dynamics, 3DVar is no longer enough, because we need to relate observations at later times to the initial state through the forward model. Strong-constraint 4DVar treats the dynamics as exact and makes the initial state x0x_0x0​ the control variable.

Cost function¶

Given observations yty_tyt​ at times t=0,1,…,Tt = 0, 1, \ldots, Tt=0,1,…,T, dynamics MtM_tMt​ propagating x0x_0x0​ to time ttt, and an observation operator HtH_tHt​ with error covariance RtR_tRt​ at each time, the cost is the 3DVar cost (5.1) summed over the window,

J(x0)=12∥x0−xb∥B−12+12∑t=0T∥yt−Ht(Mt(x0))∥Rt−12J(x_0) = \frac{1}{2} \|x_0 - x_b\|^2_{B^{-1}} + \frac{1}{2} \sum_{t=0}^{T} \|y_t - H_t(M_t(x_0))\|^2_{R_t^{-1}}J(x0​)=21​∥x0​−xb​∥B−12​+21​t=0∑T​∥yt​−Ht​(Mt​(x0​))∥Rt−1​2​
(6.1)

Strong-constraint means the model is treated as exact: any x0x_0x0​ determines the trajectory (1.3) exactly, and model error is not admitted (WeakFourDVar in chapter 7 admits it). The gradient combines the background term with the adjoint of every forward step,

∇J(x0)=B−1(x0−xb)+∑t=0T(Mt′)⊤Ht′⊤Rt−1(Ht(Mt(x0))−yt)\nabla J(x_0) = B^{-1}(x_0 - x_b) + \sum_{t=0}^{T} (M'_t)^\top H'_t{}^\top R_t^{-1} (H_t(M_t(x_0)) - y_t)∇J(x0​)=B−1(x0​−xb​)+t=0∑T​(Mt′​)⊤Ht′​⊤Rt−1​(Ht​(Mt​(x0​))−yt​)
(6.2)

where Mt′M'_tMt′​ is the tangent-linear model of MtM_tMt​ at x0x_0x0​ and Ht′H'_tHt′​ the Jacobian of HtH_tHt​ at Mt(x0)M_t(x_0)Mt​(x0​). In hand-coded operational 4DVar, (Mt′)⊤(M'_t)^\top(Mt′​)⊤ is the adjoint model, historically a major engineering effort (Talagrand and Courtier 1987, Errico 1997). With diffrax, it is a constructor argument.

The truth xtruex_\text{true}xtrue​ is a state on the attractor; the background is xb=xtrue+Lξx_b = x_\text{true} + L \xixb​=xtrue​+Lξ with B=LL⊤B = L L^\topB=LL⊤ a Gaussian correlation of length scale ℓ=2\ell = 2ℓ=2 sites (plus a 10-3 jitter), and every second site is observed at every time, yt=Mt(xtrue)+εty_t = M_t(x_\text{true}) + \varepsilon_tyt​=Mt​(xtrue​)+εt​, with R=IR = IR=I. It prints RMSE of x_b 1.44, of x₀* 0.63. With the default lx.CG covariance solver this BBB (condition number about 5×1035 \times 10^35×103) makes the B−1B^{-1}B−1 solve return non-finite values, so the block passes cov_solver=lx.Cholesky().

Three slots control the gradient:

  • checkpoint rematerialises the rollout in reverse mode (True, or a block length k), for any per-step forward; the gradient is the same and the memory smaller (chapter 3).

  • forward_adjoint is a diffrax.AbstractAdjoint for a forward that integrates with diffrax and implements with_adjoint(adjoint) (SupportsForwardAdjoint), for example dfx.BacksolveAdjoint() for constant memory over long windows. Any other forward raises ValueError.

  • minimiser_adjoint controls how gradients flow back through the outer minimiser, as for ThreeDVar (chapter 5).

Large controls: first-order minimisers¶

minimiser= takes an optimistix.AbstractMinimiser (the default is optx.BFGS(rtol=1e-6, atol=1e-6); chapter 5 lists the choices) or any Minimiser: a callable minimiser(cost_fn, x0, batch) -> x_star over a pytree control. BFGS keeps a dense inverse-Hessian estimate, which is not viable when the control is 105 network weights. OptaxMinimiser runs a first-order optax optimiser instead, in a jax.lax.while_loop, and stops at max_steps, at a gradient norm below gtol, at a step below atol + rtol·‖x‖, or after patience steps whose cost is worse than the best by more than round-off. (There is no relative cost-change test: next to a large irreducible misfit the cost change rounds to zero in float32 long before xxx converges.) An optional polish optimiser (e.g. optax.lbfgs()), with its own tight tolerances, finishes from there.

It prints RMSE of x₀* 0.26; the NonlinearCG run above stops at its 200-step cap before it converges.

minimiser_adjoint still applies. Its default, ImplicitAdjoint, is exact only at a stationary point, ∇J(x⋆)=0\nabla J(x^\star) = 0∇J(x⋆)=0, which a first-order optimiser stopped early does not guarantee: OptaxMinimiser reports ∥∇J(x⋆)∥2\lVert \nabla J(x^\star) \rVert_2∥∇J(x⋆)∥2​ in MinimiseResult.grad_norm; check it before trusting gradients through the analysis. result.cost is differentiable (envelope theorem). OptimistixMinimiser() is the default made explicit and returns exactly what the default model returns.

The adjoint problem¶

The gradient (6.2) reads “integrate the trajectory forward, then propagate the observation residuals backward through the adjoint of the dynamics.” In equations, this is the backward sweep

λT=HT′⊤RT−1(HT(xT)−yT)\lambda_T = H'_T{}^\top R_T^{-1} (H_T(x_T) - y_T)λT​=HT′​⊤RT−1​(HT​(xT​)−yT​)
(6.4)
λt−1=(Mt←t−1′)⊤λt+Ht−1′⊤Rt−1−1(Ht−1(xt−1)−yt−1)\lambda_{t-1} = (M'_{t \leftarrow t-1})^\top \lambda_t + H'_{t-1}{}^\top R_{t-1}^{-1} (H_{t-1}(x_{t-1}) - y_{t-1})λt−1​=(Mt←t−1′​)⊤λt​+Ht−1′​⊤Rt−1−1​(Ht−1​(xt−1​)−yt−1​)
(6.5)
∇x0J=B−1(x0−xb)+λ0\nabla_{x_0} J = B^{-1}(x_0 - x_b) + \lambda_0∇x0​​J=B−1(x0​−xb​)+λ0​
(6.6)

where λt\lambda_tλt​ is the adjoint state at time ttt and Mt←t−1′M'_{t \leftarrow t-1}Mt←t−1′​ is the tangent-linear model of the single step from t−1t - 1t−1 to ttt, so that Mt′M'_tMt′​ in (6.2) is the product of these one-step tangents. This is exactly what diffrax.RecursiveCheckpointAdjoint or BacksolveAdjoint compute under the hood. Vardax just composes them into the cost-gradient call.

Algorithm¶

Written out, the cost (6.1) rolls the trajectory forward, sums the whitened misfit over the window and adds the background term, and optimistix.minimise differentiates through the rollout by reverse mode, which is the backward sweep (6.4) to (6.6). StrongFourDVar builds the same cost (with optional jax.checkpoint blocks and a forward_adjoint), so the hand-written one reaches the same minimum. The block continues the one above.

When the window is long¶

For T=100T = 100T=100+ assimilation cycles, the forward trajectory dominates memory. Four strategies:

  1. checkpoint=True (or a block length). Works with any per-step forward, with 3 to 4 times less gradient memory on Lorenz-96 (chapter 3).

  2. dfx.BacksolveAdjoint() (via forward_adjoint=, for a SupportsForwardAdjoint forward) solves the adjoint ODE backwards in time, with O(1)O(1)O(1) memory in the trajectory length. Reverse-time stiffness can require an implicit integrator (dfx.Kvaerno5, dfx.ImplicitEuler).

  3. dfx.RecursiveCheckpointAdjoint(checkpoints=N) (also via forward_adjoint=) stores NNN checkpoints and recomputes the segments between them, with O(T)O(\sqrt{T})O(T​) memory.

  4. Shorter windows. Run multiple StrongFourDVar analyses with shorter windows and cycle them via pipekit_cycle.DACycle. This is what operational systems do.

For most research-scale problems with T≤20T \le 20T≤20, the defaults (plain reverse mode, the forward’s own adjoint) are fine.

When the dynamics are nonlinear¶

The 4DVar cost (6.1) is nonconvex when MtM_tMt​ is nonlinear, so multiple local minima exist (and matter, especially for chaotic systems like Lorenz). Strategies:

  • Multi-start. Minimise from several perturbed first guesses and keep the lowest cost. vardax has no helper for this yet: the models start every minimisation from xbx_bxb​, so a multi-start needs a first guess separate from the background.

  • Quasi-static gradient. Use a warm-start from a previous cycle (the usual operational pattern).

  • Switch to IncrementalFourDVar (chapter 8): the outer Gauss-Newton iterations relinearise around the current iterate, which is more robust than NonlinearCG on the full nonlinear cost.

When StrongFourDVar is the right answer¶

Use StrongFourDVar for multi-time observations with dynamics when model error is small (within the noise floor of the observations) and you want an optimistix or optax minimiser directly on the full nonlinear cost. For operational 4DVar with structured priors, IncrementalFourDVar solves the same problem faster; chapter 8 says when to switch. If model error matters, use WeakFourDVar (chapter 7).
