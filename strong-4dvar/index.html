Strong-constraint 4DVar

When observations are spread across an assimilation window and the state evolves through known dynamics, 3DVar is no longer enough, because we need to relate observations at later times to the initial state through the forward model. Strong-constraint 4DVar treats the dynamics as exact and makes the initial state x0\vect{x}_0x0​ the control variable.

Cost function¶

Given observations yt\vect{y}_tyt​ at times t=0,1,…,Tt = 0, 1, \ldots, Tt=0,1,…,T, a forward model fff whose ttt-fold composition ftf_tft​ propagates x0\vect{x}_0x0​ to time ttt (so xt=ft(x0)\vect{x}_t = f_t(\vect{x}_0)xt​=ft​(x0​) and f0f_0f0​ is the identity), and an observation operator hth_tht​ with error covariance Σε,t\gmat{\Sigma}_{\varepsilon,t}Σε,t​ at each time, the cost is the 3DVar cost (5.1) summed over the window,

J(x0)=12∥x0−μx∥Σx−12+12∑t=0T∥yt−ht(ft(x0))∥Σε,t−12\mathcal{J}(\vect{x}_0) = \frac{1}{2} \Vert \vect{x}_0 - \gvect{\mu}_x \Vert^2_{\gmat{\Sigma}_x^{-1}} + \frac{1}{2} \sum_{t=0}^{T} \Vert \vect{y}_t - h_t(f_t(\vect{x}_0)) \Vert^2_{\gmat{\Sigma}_{\varepsilon,t}^{-1}}J(x0​)=21​∥x0​−μx​∥Σx−1​2​+21​t=0∑T​∥yt​−ht​(ft​(x0​))∥Σε,t−1​2​
(6.1)

Strong-constraint means the model is treated as exact: any x0\vect{x}_0x0​ determines the trajectory (1.3) exactly, and model error is not admitted (WeakFourDVar in chapter 7 admits it). The gradient combines the background term with the adjoint of every forward step,

∇x0J(x0)=Σx−1(x0−μx)+∑t=0TFt←0⊤Ht⊤Σε,t−1(ht(ft(x0))−yt)\nabla_{\vect{x}_0} \mathcal{J}(\vect{x}_0) = \gmat{\Sigma}_x^{-1}(\vect{x}_0 - \gvect{\mu}_x) + \sum_{t=0}^{T} \mat{F}_{t \leftarrow 0}^\top \mat{H}_t^\top \gmat{\Sigma}_{\varepsilon,t}^{-1} (h_t(f_t(\vect{x}_0)) - \vect{y}_t)∇x0​​J(x0​)=Σx−1​(x0​−μx​)+t=0∑T​Ft←0⊤​Ht⊤​Σε,t−1​(ht​(ft​(x0​))−yt​)
(6.2)

where Ft←0\mat{F}_{t \leftarrow 0}Ft←0​ is the tangent-linear model of ftf_tft​ at x0\vect{x}_0x0​ and Ht\mat{H}_tHt​ the Jacobian of hth_tht​ at ft(x0)f_t(\vect{x}_0)ft​(x0​). The shapes are x0,μx∈RDx\vect{x}_0, \gvect{\mu}_x \in \mathbb{R}^{D_x}x0​,μx​∈RDx​, yt∈RDy\vect{y}_t \in \mathbb{R}^{D_y}yt​∈RDy​, ft:RDx→RDxf_t: \mathbb{R}^{D_x} \to \mathbb{R}^{D_x}ft​:RDx​→RDx​, ht:RDx→RDyh_t: \mathbb{R}^{D_x} \to \mathbb{R}^{D_y}ht​:RDx​→RDy​, Σx,Ft←0∈RDx×Dx\gmat{\Sigma}_x, \mat{F}_{t \leftarrow 0} \in \mathbb{R}^{D_x \times D_x}Σx​,Ft←0​∈RDx​×Dx​, Σε,t∈RDy×Dy\gmat{\Sigma}_{\varepsilon,t} \in \mathbb{R}^{D_y \times D_y}Σε,t​∈RDy​×Dy​ and Ht∈RDy×Dx\mat{H}_t \in \mathbb{R}^{D_y \times D_x}Ht​∈RDy​×Dx​. In hand-coded operational 4DVar, Ft←0⊤\mat{F}_{t \leftarrow 0}^\topFt←0⊤​ is the adjoint model, historically a major engineering effort (Talagrand and Courtier 1987, Errico 1997). With diffrax, it is a constructor argument.

Implementation in vardax¶

The truth xtrue\vect{x}_\text{true}xtrue​ is a state on the attractor; the background is μx=xtrue+Lxξ\gvect{\mu}_x = \vect{x}_\text{true} + \mat{L}_x \gvect{\xi}μx​=xtrue​+Lx​ξ with Σx=LxLx⊤\gmat{\Sigma}_x = \mat{L}_x \mat{L}_x^\topΣx​=Lx​Lx⊤​ a Gaussian correlation of length scale ℓ=2\ell = 2ℓ=2 sites (plus a 10-3 jitter) and ξ∼N(0,I)\gvect{\xi} \sim \mathcal{N}(\mathbf{0}, \mat{I})ξ∼N(0,I), and every second site is observed at every time, yt=ft(xtrue)+εt\vect{y}_t = f_t(\vect{x}_\text{true}) + \gvect{\varepsilon}_tyt​=ft​(xtrue​)+εt​, with Σε=I\gmat{\Sigma}_\varepsilon = \mat{I}Σε​=I and Dy=DxD_y = D_xDy​=Dx​. hth_tht​ is the identity on the observed sites, so the mask mt\vect{m}_tmt​ does the selection.

It prints RMSE of μ_x 1.44, of x₀⋆ 0.63. With the default lx.CG covariance solver this Σx\gmat{\Sigma}_xΣx​ (condition number about 5×1035 \times 10^35×103) makes the Σx−1\gmat{\Sigma}_x^{-1}Σx−1​ solve return non-finite values, so the block passes cov_solver=lx.Cholesky().

Three slots control the gradient:

  • checkpoint rematerialises the rollout in reverse mode (True, or a block length k) through integrix.adjoint.checkpointed_scan, for any per-step forward; the gradient is the same and the memory smaller (chapter 3).

  • forward_adjoint is a diffrax.AbstractAdjoint for a forward that integrates with diffrax and implements with_adjoint(adjoint) (SupportsForwardAdjoint), for example dfx.BacksolveAdjoint() for constant memory over long windows. Any other forward raises ValueError.

  • minimiser_adjoint controls how gradients flow back through the outer minimiser, as for ThreeDVar (chapter 5).

Large controls: first-order minimisers¶

minimiser= takes an optimistix.AbstractMinimiser (the default is optx.BFGS(rtol=1e-6, atol=1e-6); chapter 5 lists the choices) or any Minimiser: a callable minimiser(cost_fn, x0, batch) -> x_star over a pytree control. BFGS keeps a dense inverse-Hessian estimate, which is not viable when the control is 105 network weights. OptaxMinimiser runs a first-order optax optimiser instead, in a jax.lax.while_loop, and stops at max_steps, at a gradient norm below gtol, at a step below atol + rtol·‖x‖, or after patience steps whose cost is worse than the best by more than round-off. (There is no relative cost-change test: next to a large irreducible misfit the cost change rounds to zero in float32 long before x\vect{x}x converges.) An optional polish optimiser (e.g. optax.lbfgs()), with its own tight tolerances, finishes from there.

It prints RMSE of x₀⋆ 0.26; the NonlinearCG run above stops at its 200-step cap before it converges.

minimiser_adjoint still applies. Its default, ImplicitAdjoint, is exact only at a stationary point, ∇θJ(θ⋆)=0\nabla_{\gvect{\theta}} \mathcal{J}(\gvect{\theta}^\star) = \mathbf{0}∇θ​J(θ⋆)=0, which a first-order optimiser stopped early does not guarantee: OptaxMinimiser reports ∥∇θJ(θ⋆)∥2\Vert \nabla_{\gvect{\theta}} \mathcal{J}(\gvect{\theta}^\star) \Vert_2∥∇θ​J(θ⋆)∥2​ in MinimiseResult.grad_norm; check it before trusting gradients through the analysis. result.cost is differentiable (envelope theorem). OptimistixMinimiser() is the default made explicit and returns exactly what the default model returns.

Reduced-basis 4DVar¶

ReducedBasisFourDVar(basis=...) minimises this cost with the control moved into a basis, x0=μx+Φz\vect{x}_0 = \gvect{\mu}_x + \gmat{\Phi} \vect{z}x0​=μx​+Φz with Dz≪DxD_z \ll D_xDz​≪Dx​ coefficients; it is the reduced strong-constraint rung of chapter 23, which owns its cost (23.5), its gradient and the Lorenz-96 comparison against this chapter’s full control.

The adjoint problem¶

The gradient (6.2) reads “integrate the trajectory forward, then propagate the observation residuals backward through the adjoint of the dynamics.” In equations, this is the backward sweep

xT†=HT⊤Σε,T−1(hT(xT)−yT)\vect{x}^\dagger_T = \mat{H}_T^\top \gmat{\Sigma}_{\varepsilon,T}^{-1} (h_T(\vect{x}_T) - \vect{y}_T)xT†​=HT⊤​Σε,T−1​(hT​(xT​)−yT​)
(6.4)

Algorithm¶

Written out, the cost (6.1) rolls the trajectory forward, sums the whitened misfit over the window and adds the background term, and optimistix.minimise differentiates through the rollout by reverse mode, which is the backward sweep (6.4) to (6.6). StrongFourDVar builds the same cost (with optional jax.checkpoint blocks and a forward_adjoint), so the hand-written one reaches the same minimum. The block continues the one above.

When the window is long¶

For T=100T = 100T=100+ assimilation cycles, the forward trajectory dominates memory. Four strategies:

  1. checkpoint=True (or a block length). Runs the rollout through integrix.adjoint.checkpointed_scan and works with any per-step forward, with 3 to 4 times less gradient memory on Lorenz-96 (chapter 3).

  2. dfx.BacksolveAdjoint() (via forward_adjoint=, for a SupportsForwardAdjoint forward) solves the adjoint ODE backwards in time, with O(1)O(1)O(1) memory in the trajectory length. Reverse-time stiffness can require an implicit integrator (dfx.Kvaerno5, dfx.ImplicitEuler).

  3. dfx.RecursiveCheckpointAdjoint(checkpoints=N) (also via forward_adjoint=) stores NNN checkpoints and recomputes the segments between them, with O(T)O(\sqrt{T})O(T​) memory.

  4. Shorter windows. Run multiple StrongFourDVar analyses with shorter windows and cycle them via pipekit_cycle.DACycle. This is what operational systems do.

For most research-scale problems with T≤20T \le 20T≤20, the defaults (plain reverse mode, the forward’s own adjoint) are fine.

When the dynamics are nonlinear¶

The 4DVar cost (6.1) is nonconvex when fff is nonlinear, so multiple local minima exist (and matter, especially for chaotic systems like Lorenz). Strategies:

  • Multi-start. Minimise from several perturbed first guesses and keep the lowest cost. vardax has no helper for this yet: the models start every minimisation from μx\gvect{\mu}_xμx​, so a multi-start needs a first guess separate from the background.

  • Quasi-static gradient. Use a warm-start from a previous cycle (the usual operational pattern).

  • Switch to IncrementalFourDVar (chapter 8): the outer Gauss-Newton iterations relinearise around the current iterate, which is more robust than NonlinearCG on the full nonlinear cost.

When StrongFourDVar is the right answer¶

Use StrongFourDVar for multi-time observations with dynamics when model error is small (within the noise floor of the observations) and you want an optimistix or optax minimiser directly on the full nonlinear cost. For operational 4DVar with structured priors, IncrementalFourDVar solves the same problem faster; chapter 8 says when to switch. If model error matters, use WeakFourDVar (chapter 7).
