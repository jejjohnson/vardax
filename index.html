vardax

JAX-native data assimilation inference.

Formerly fourdvarjax — renamed to vardax.

Status

All seven analysis methods ship and all seven satisfy pipekit_cycle.AnalysisStep via .as_analysis_step(). Import them from the package root (import vardax as vdx; vdx.StrongFourDVar): there is no vardax.models or vardax.obs_operators module. The vardax.adjoints, vardax.amortized and vardax.cycle submodules are bound too, and a few symbols live only there — AbstractAdjoint is vardax.adjoints.AbstractAdjoint, not vardax.AbstractAdjoint. Individual components may still be stubs where a chapter says so (the flow and score heads of amortized inference are the current ones); see boundaries for what vardax will and will not own. (The package was previously published as fourdvarjax v0.1.x; vardax is now the canonical name.)

vardax provides the seven classical and modern DA analysis methods as peer pipekit_cycle.AnalysisStep implementations:

The single equation¶

Every analysis method in vardax is a special case of

where the window has TTT steps and T+1T + 1T+1 times, xt=f(xt−1)+ηt\vect{x}_t = f(\vect{x}_{t-1}) + \gvect{\eta}_txt​=f(xt−1​)+ηt​ is the trajectory from x0\vect{x}_0x0​ (with ηt=0\gvect{\eta}_t = \mathbf{0}ηt​=0 when the model-error term is absent), and the shapes are xt,μx,ηt∈RDx\vect{x}_t, \gvect{\mu}_x, \gvect{\eta}_t \in \mathbb{R}^{D_x}xt​,μx​,ηt​∈RDx​, yt∈RDy\vect{y}_t \in \mathbb{R}^{D_y}yt​∈RDy​, f:RDx→RDxf: \mathbb{R}^{D_x} \to \mathbb{R}^{D_x}f:RDx​→RDx​, ht:RDx→RDyh_t: \mathbb{R}^{D_x} \to \mathbb{R}^{D_y}ht​:RDx​→RDy​, Σx,Ση,t∈RDx×Dx\gmat{\Sigma}_x, \gmat{\Sigma}_{\eta,t} \in \mathbb{R}^{D_x \times D_x}Σx​,Ση,t​∈RDx​×Dx​ and Σε,t∈RDy×Dy\gmat{\Sigma}_{\varepsilon,t} \in \mathbb{R}^{D_y \times D_y}Σε,t​∈RDy​×Dy​.

Different methods specialise differently:

  • T=0T = 0T=0 + linear H\mat{H}H + Gaussian Σx\gmat{\Sigma}_xΣx​, Σε\gmat{\Sigma}_\varepsilonΣε​ → OptimalInterpolation (closed form)

  • T=0T = 0T=0 + nonlinear hhh → ThreeDVar

  • T>0T > 0T>0, model-error term absent → StrongFourDVar / IncrementalFourDVar

  • T>0T > 0T>0, model-error term active → WeakFourDVar

  • Learned gaeg_\text{ae}gae​ replacing ∥x−μx∥Σx−12\Vert \vect{x} - \gvect{\mu}_x \Vert^2_{\gmat{\Sigma}_x^{-1}}∥x−μx​∥Σx−1​2​ + learned inner solver → FourDVarNet1D / FourDVarNet2D

  • Direct posterior head q(x∣y;ν)q(\vect{x} \mid \vect{y}; \gvect{\nu})q(x∣y;ν) → AmortizedPosterior

See the Problem Setting chapter for the full derivation.

Installation¶

git clone https://github.com/jejjohnson/vardax.git
cd vardax
uv sync --all-extras

vardax is not yet on PyPI; install from the checkout.

Quickstart: optimal interpolation¶

A single forward pass: no iteration, no convergence criterion. The analysis is the Σx\gmat{\Sigma}_xΣx​/Σε\gmat{\Sigma}_\varepsilonΣε​-weighted combination of background and observations, so it beats both. The state is x∈RDx\vect{x} \in \mathbb{R}^{D_x}x∈RDx​ with Dx=64D_x = 64Dx​=64 cells, the background mean is μx=0\gvect{\mu}_x = \mathbf{0}μx​=0 with Σx=I\gmat{\Sigma}_x = \mat{I}Σx​=I, and the observation noise has Σε=σε2I\gmat{\Sigma}_\varepsilon = \sigma_\varepsilon^2 \mat{I}Σε​=σε2​I with σε=0.3\sigma_\varepsilon = 0.3σε​=0.3.

It prints RMS error: background 0.72, observations 0.33, analysis 0.31.

For a correlated background, pass any lineax operator in place of the identity, such as a dense kernel matrix or a structured operator from gaussx. Posterior covariance is a separate concern, handled by the posterior adapters rather than a method on the model.

Quickstart: incremental 4DVar¶

Gauss-Newton outer loops around a conjugate-gradient inner solve, on a window of Lorenz-63 observed every other step. The state has Dx=3D_x = 3Dx​=3 components and the window T=20T = 20T=20 steps, so T+1=21T + 1 = 21T+1=21 times; Σx=4I\gmat{\Sigma}_x = 4 \mat{I}Σx​=4I, Σε=σε2I\gmat{\Sigma}_\varepsilon = \sigma_\varepsilon^2 \mat{I}Σε​=σε2​I with σε=0.5\sigma_\varepsilon = 0.5σε​=0.5, and the mask selects the observed times.

It prints background error 2.60, analysis error 0.79.

Cycling any model through pipekit_cycle.DACycle¶

All seven methods satisfy pipekit_cycle.AnalysisStep via .as_analysis_step(), so the orchestration code is identical for each of them. The block below continues the incremental quickstart: it observes the whole Lorenz-63 state at every time of the window, and cycles an OI analysis around each forecast.

It prints 20 cycles, final error 0.54.

Swap OptimalInterpolation for IncrementalFourDVar for FourDVarNet1D by changing the analysis_step slot. Nothing else in the pipeline changes.

What each method’s built-in adapter does with the forecast differs, though, and the shapes have to line up: the 4DVar adapters re-solve against the background the model was constructed with and expect a batched observation window, so a cycle that uses each forecast as the next background supplies a small custom AnalysisStep. Notebook 16 shows that pattern end to end.

Ecosystem¶

vardax does not own forward models, optimisers, ODE solvers, ensemble methods, or structured linear algebra. It composes them:
