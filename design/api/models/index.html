Layer 2 — Models

Seven peer classes, each satisfying pipekit_cycle.AnalysisStep via .as_analysis_step(). None inherits from any other; the differences sit in the algorithm, not in the type hierarchy.

ClassMethodDecision
OptimalInterpolationBLUE / OI — closed-form linear-GaussianD14, D16
ThreeDVar3D variational, nonlinear HHH, single timeD14
StrongFourDVar4DVar, control = x0x_0x0​, exact dynamicsD14
WeakFourDVar4DVar, control = (x0,η1,…,ηT)(x_0, \eta_1, \ldots, \eta_T)(x0​,η1​,…,ηT​)D14
IncrementalFourDVarGN outer + CG inner + CVT (fast StrongFourDVar)D11

All seven accept the same Batch* types and the same observation operator family. The user picks the method that matches the regime.

OptimalInterpolation — BLUE / OI¶

Mathematical formulation¶

The Best Linear Unbiased Estimator for linear-Gaussian state estimation:

x∗=xb+K(y−Hxb),K=BH⊤(HBH⊤+R)−1x^* = x_b + K(y - H x_b), \qquad K = B H^\top (H B H^\top + R)^{-1}x∗=xb​+K(y−Hxb​),K=BH⊤(HBH⊤+R)−1
(1)

with posterior covariance

P∗=(B−1+H⊤R−1H)−1=(I−KH)B.P^* = (B^{-1} + H^\top R^{-1} H)^{-1} = (I - K H) B.P∗=(B−1+H⊤R−1H)−1=(I−KH)B.
(2)

Choice of form (Sherman-Morrison-Woodbury): use the RRR-space form when the observation dimension mmm is smaller than the state dimension nnn; the BBB-space form otherwise. gaussx handles structured BBB and RRR without materialising dense matrices.

Class contract¶

When to use¶

  • HHH is linear (or the linearisation around xbx_bxb​ is good enough)

  • BBB, RRR, HHH are Gaussian (or close enough that the posterior is unimodal Gaussian)

  • Static field (no dynamics) or a single timestep

If any of these fail, ThreeDVar (nonlinear HHH) or StrongFourDVar / IncrementalFourDVar (dynamics) is the right choice. OptimalInterpolation.__init__ validates linearity and refuses nonlinear obs operators with a clear error message.

ThreeDVar — 3D Variational¶

Mathematical formulation¶

Minimise

J(x)=12∥x−xb∥B−12+12∥y−H(x)∥R−12J(x) = \tfrac{1}{2} \|x - x_b\|^2_{B^{-1}} + \tfrac{1}{2} \|y - H(x)\|^2_{R^{-1}}J(x)=21​∥x−xb​∥B−12​+21​∥y−H(x)∥R−12​
(3)

over xxx. For nonlinear HHH, solve iteratively via Gauss-Newton, BFGS, or NonlinearCG (chosen by the user via the minimiser slot).

In the linear-Gaussian limit, ThreeDVar recovers OptimalInterpolation exactly — the conformance test suite verifies this agreement.

Class contract¶

When to use¶

  • Nonlinear HHH (e.g. averaging kernel + nonlinear retrieval)

  • Single timestep (snapshot inversion)

  • Posterior assumed Gaussian-around-MAP (LaplaceCovariance adapter)

StrongFourDVar — Strong-constraint 4DVar¶

Mathematical formulation¶

Control variable is the initial state x0x_0x0​ alone; dynamics MtM_tMt​ are treated as exact:

J(x0)=12∥x0−xb∥B−12+12∑t=0T∥yt−Ht(Mt(x0))∥Rt−12J(x_0) = \tfrac{1}{2} \|x_0 - x_b\|^2_{B^{-1}} + \tfrac{1}{2} \sum_{t=0}^{T} \|y_t - H_t(M_t(x_0))\|^2_{R_t^{-1}}J(x0​)=21​∥x0​−xb​∥B−12​+21​t=0∑T​∥yt​−Ht​(Mt​(x0​))∥Rt−1​2​
(4)

Gradients of JJJ with respect to x0x_0x0​ are computed by integrating the adjoint of MtM_tMt​ backwards in time — vardax delegates this to diffrax.AbstractAdjoint (see Decision D15). The default RecursiveCheckpointAdjoint is autodiff with recursive checkpointing; BacksolveAdjoint solves the continuous adjoint ODE in reverse time (constant memory, good for long windows).

Class contract¶

When to use¶

  • Multi-timestep observations of a state with known dynamics

  • Model error is small enough to ignore

  • General-purpose 4DVar (use IncrementalFourDVar for the operational fast path)

WeakFourDVar — Weak-constraint 4DVar¶

Mathematical formulation¶

Control vector is augmented to include per-step model error:

η=(η1,…,ηT),xt=Mtfree(xt−1)+ηt\boldsymbol{\eta} = (\eta_1, \ldots, \eta_T), \quad x_t = M_t^\text{free}(x_{t-1}) + \eta_tη=(η1​,…,ηT​),xt​=Mtfree​(xt−1​)+ηt​
(5)

with cost

J(x0,η)=12∥x0−xb∥B−12+12∑t∥yt−Ht(xt)∥Rt−12+12∑t∥ηt∥Qt−12J(x_0, \boldsymbol{\eta}) = \tfrac{1}{2} \|x_0 - x_b\|^2_{B^{-1}} + \tfrac{1}{2} \sum_t \|y_t - H_t(x_t)\|^2_{R_t^{-1}} + \tfrac{1}{2} \sum_t \|\eta_t\|^2_{Q_t^{-1}}J(x0​,η)=21​∥x0​−xb​∥B−12​+21​t∑​∥yt​−Ht​(xt​)∥Rt−1​2​+21​t∑​∥ηt​∥Qt−1​2​
(6)

The model-error covariance QtQ_tQt​ is a separate input.

Class contract¶

When to use¶

  • Multi-timestep observations with non-negligible model error

  • Long assimilation windows where dynamics drift away from observations

  • Climatological or seasonal mismatch between MtfreeM_t^\text{free}Mtfree​ and reality

WeakFourDVar is computationally heavier than StrongFourDVar because the control vector dimension scales with TTT. Use sparingly; consider StrongFourDVar with a learned φθ\varphi_\thetaφθ​ as a cheaper alternative.

IncrementalFourDVar — Operational Fast Path¶

Mathematical formulation¶

Functionally equivalent to StrongFourDVar, but uses Gauss-Newton outer iterations on the full nonlinear cost with CG / Lanczos inner iterations on the linearised quadratic subproblem. At each outer iterate x(k)x^{(k)}x(k) (with x(0)=xbx^{(0)} = x_bx(0)=xb​; the background xbx_bxb​ stays fixed), linearise MtM_tMt​ and HtH_tHt​ via jax.linearize:

δJ(δx)=12∥x(k)+δx−xb∥B−12+12∑t∥dt(k)−Ht′Mt′δx∥Rt−12\delta J(\delta x) = \tfrac{1}{2} \|x^{(k)} + \delta x - x_b\|^2_{B^{-1}} + \tfrac{1}{2} \sum_t \|d_t^{(k)} - H'_t M'_t \delta x\|^2_{R_t^{-1}}δJ(δx)=21​∥x(k)+δx−xb​∥B−12​+21​t∑​∥dt(k)​−Ht′​Mt′​δx∥Rt−1​2​
(7)

with innovation dt(k)=yt−Ht(Mt(x(k)))d_t^{(k)} = y_t - H_t(M_t(x^{(k)}))dt(k)​=yt​−Ht​(Mt​(x(k))). Solve HGN δx∗=−∇J(x(k))\mathbf{H}_\text{GN}\,\delta x^* = -\nabla J(x^{(k)})HGN​δx∗=−∇J(x(k)) by CG (the right-hand side keeps the background misfit −B−1(x(k)−xb)-B^{-1}(x^{(k)} - x_b)−B−1(x(k)−xb​)), update x(k+1)=x(k)+δx∗x^{(k+1)} = x^{(k)} + \delta x^*x(k+1)=x(k)+δx∗, relinearise.

Control-variable transform (CVT): set χ=B−1/2(δx)\chi = B^{-1/2}(\delta x)χ=B−1/2(δx); the prior term becomes ∥χ∥2\|\chi\|^2∥χ∥2 and the inner CG operates on a well-conditioned problem. B1/2B^{1/2}B1/2 comes from gaussx.MaternLinearOperator.half().

Class contract¶

IncrementalConfig carries n_outer, n_inner, cg_atol, cg_rtol, cvt: bool (default True).

When to use¶

  • Operational 4DVar (ECMWF-style)

  • Long assimilation windows where general StrongFourDVar would be slow

  • When you want posterior covariance via Gauss-Newton Hessian without a separate adapter pass (the Hessian is already assembled in the last outer iteration)

FourDVarNet — Learned 4DVar¶

Mathematical formulation¶

Replace the Gaussian prior ∥x−xb∥B−12\|x - x_b\|^2_{B^{-1}}∥x−xb​∥B−12​ with a learned prior ∥x−φθ(x)∥2\|x - \varphi_\theta(x)\|^2∥x−φθ​(x)∥2, where φθ\varphi_\thetaφθ​ is an autoencoder (BilinAE, ConvAE, MLPAE). Replace the standard gradient-descent inner solver with a learned gradient modulator Φϕ\Phi_\phiΦϕ​:

xk+1=xk−Φϕ(∇xJ(xk),  hk)x_{k+1} = x_k - \Phi_\phi(\nabla_x J(x_k),\; h_k)xk+1​=xk​−Φϕ​(∇x​J(xk​),hk​)
(8)

with J(x)=αobs∥H(x)−y∥2+αprior∥x−φθ(x)∥2J(x) = \alpha_\text{obs} \|H(x) - y\|^2 + \alpha_\text{prior} \|x - \varphi_\theta(x)\|^2J(x)=αobs​∥H(x)−y∥2+αprior​∥x−φθ​(x)∥2.

Training minimises reconstruction MSE against ground truth:

L(θ,ϕ)=∥x∗(θ,ϕ)−xtrue∥2.\mathcal{L}(\theta, \phi) = \|x^*(\theta, \phi) - x_\text{true}\|^2.L(θ,ϕ)=∥x∗(θ,ϕ)−xtrue​∥2.
(9)

The training gradient ∇θ,ϕL\nabla_{\theta, \phi} \mathcal{L}∇θ,ϕ​L flows through the inner solver via the solver_adjoint slot (an optimistix.AbstractAdjoint).

When to use¶

  • Research / benchmarks where ground-truth xtruex_\text{true}xtrue​ is available for training

  • Data-rich regimes (the learned φθ\varphi_\thetaφθ​ shines)

  • Settings where the classical BBB is hard to specify or known to be inadequate

AmortizedPosterior — Direct head¶

Mathematical formulation¶

Learn a conditional density qϕ(x∣y)q_\phi(x \mid y)qϕ​(x∣y) that approximates p(x∣y)p(x \mid y)p(x∣y). Train on simulated pairs from the prior and forward:

ϕ∗=arg⁡min⁡ϕ  E(x,y)∼p(x,y)  KL(qϕ(⋅∣y) ∥ p(⋅∣y)).\phi^* = \underset{\phi}{\arg\min}\; \mathbb{E}_{(x, y) \sim p(x, y)}\; \mathrm{KL}\big(q_\phi(\cdot \mid y) \,\|\, p(\cdot \mid y)\big).ϕ∗=ϕargmin​E(x,y)∼p(x,y)​KL(qϕ​(⋅∣y)∥p(⋅∣y)).
(10)

Head variants: conditional normalising flow (gauss_flows), score-based diffusion, regression (Gaussian heads).

Class contract¶

When to use¶

  • Real-time inference (single forward pass, sub-second)

  • Many independent events (catalog reprocessing)

  • After validating against a StrongFourDVar / IncrementalFourDVar oracle on a held-out set (six-step cycle gates, Decision D12)

AnalysisStep adapter (Decision D8)¶

All seven classes expose .as_analysis_step():

The adapter shells the model’s __call__ to match the pipekit-cycle analysis signature. The OptimalInterpolation and ThreeDVar adapters analyse around forecast (the background xbx_bxb​, not the model’s prior_mean) and use the cycle’s obs_op and obs_err_cov (HHH and RRR; None falls back to the model’s own), keeping the model’s BBB. Use it in pipekit_cycle.DACycle:

The same pipeline accepts OptimalInterpolation, ThreeDVar, StrongFourDVar, WeakFourDVar, IncrementalFourDVar, FourDVarNet, or AmortizedPosterior — what changes is the inference algorithm, not the orchestration code.

Linear-Gaussian baseline (Decision D14 invariant)¶

In the linear-Gaussian limit (linear HHH, Gaussian BBB and RRR), all seven methods must agree:

OptimalInterpolation(batch)
  ≈ ThreeDVar(batch)                                # iterative GN
  ≈ StrongFourDVar(batch)         (T = 0)
  ≈ WeakFourDVar(batch)           (T = 0, η = 0)
  ≈ IncrementalFourDVar(batch)    (T = 0)
  ≈ FourDVarNet(batch)            (IdentityPrior, n_steps large)
  ≈ AmortizedPosterior(batch)     (trained to convergence on this regime)

tests/test_linear_gaussian_agreement.py enforces this — it is the canonical correctness baseline. If a new analysis method disagrees with OptimalInterpolation in the linear-Gaussian limit, something is wrong.

Library code (Decision D5) — encode correct differentiation through whichever inner algorithm the model uses (4DVarNet inner solver, amortized head, …):

Only FourDVarNet and AmortizedPosterior have learned parameters and therefore use train_step / eval_step. The classical methods are non-learnable — there are no parameters to optimise over (the prior covariance BBB is supplied, not learned).
