Layer 2 — Models

Seven peer classes, each satisfying pipekit_cycle.AnalysisStep via .as_analysis_step(). None inherits from any other; the differences sit in the algorithm, not in the type hierarchy.

ClassMethodDecision
OptimalInterpolationBLUE / OI — closed-form linear-GaussianD14, D16
ThreeDVar3D variational, nonlinear hhh, single timeD14
StrongFourDVar4DVar, control = x0\vect{x}_0x0​, exact dynamicsD14
WeakFourDVar4DVar, control = (x0,η1,…,ηT)(\vect{x}_0, \gvect{\eta}_1, \ldots, \gvect{\eta}_T)(x0​,η1​,…,ηT​)D14
IncrementalFourDVarGN outer + CG inner + CVT (fast StrongFourDVar)D11

All seven accept the same Batch* types and the same observation operator family. The user picks the method that matches the regime.

OptimalInterpolation — BLUE / OI¶

Mathematical formulation¶

The Best Linear Unbiased Estimator for linear-Gaussian state estimation:

x⋆=μx+G(y−Hμx),G=ΣxH⊤(HΣxH⊤+Σε)−1\vect{x}^\star = \gvect{\mu}_x + \mat{G} (\vect{y} - \mat{H} \gvect{\mu}_x), \qquad \mat{G} = \gmat{\Sigma}_x \mat{H}^\top (\mat{H} \gmat{\Sigma}_x \mat{H}^\top + \gmat{\Sigma}_\varepsilon)^{-1}x⋆=μx​+G(y−Hμx​),G=Σx​H⊤(HΣx​H⊤+Σε​)−1
(1)

with posterior covariance

Σx∣y=(Σx−1+H⊤Σε−1H)−1=(I−GH)Σx.\gmat{\Sigma}_{x \mid y} = (\gmat{\Sigma}_x^{-1} + \mat{H}^\top \gmat{\Sigma}_\varepsilon^{-1} \mat{H})^{-1} = (\mat{I} - \mat{G} \mat{H}) \gmat{\Sigma}_x.Σx∣y​=(Σx−1​+H⊤Σε−1​H)−1=(I−GH)Σx​.
(2)

Choice of form (Sherman-Morrison-Woodbury): use the Σε\gmat{\Sigma}_\varepsilonΣε​-space form when the observation dimension DyD_yDy​ is smaller than the state dimension DxD_xDx​; the Σx\gmat{\Sigma}_xΣx​-space form otherwise. gaussx handles structured Σx\gmat{\Sigma}_xΣx​ and Σε\gmat{\Sigma}_\varepsilonΣε​ without materialising dense matrices.

Class contract¶

When to use¶

  • hhh is linear (or the linearisation around μx\gvect{\mu}_xμx​ is good enough)

  • Σx\gmat{\Sigma}_xΣx​, Σε\gmat{\Sigma}_\varepsilonΣε​, hhh are Gaussian (or close enough that the posterior is unimodal Gaussian)

  • Static field (no dynamics) or a single timestep

If any of these fail, ThreeDVar (nonlinear hhh) or StrongFourDVar / IncrementalFourDVar (dynamics) is the right choice. OptimalInterpolation.__init__ validates linearity and refuses nonlinear obs operators with a clear error message.

ThreeDVar — 3D Variational¶

Mathematical formulation¶

Minimise

J(x)=12∥x−μx∥Σx−12+12∥y−h(x)∥Σε−12\mathcal{J}(\vect{x}) = \frac{1}{2} \Vert \vect{x} - \gvect{\mu}_x \Vert^2_{\gmat{\Sigma}_x^{-1}} + \frac{1}{2} \Vert \vect{y} - h(\vect{x}) \Vert^2_{\gmat{\Sigma}_\varepsilon^{-1}}J(x)=21​∥x−μx​∥Σx−1​2​+21​∥y−h(x)∥Σε−1​2​
(3)

over x\vect{x}x. For nonlinear hhh, solve iteratively via Gauss-Newton, BFGS, or NonlinearCG (chosen by the user via the minimiser slot).

In the linear-Gaussian limit, ThreeDVar recovers OptimalInterpolation exactly — the conformance test suite verifies this agreement.

Class contract¶

When to use¶

  • Nonlinear hhh (e.g. averaging kernel + nonlinear retrieval)

  • Single timestep (snapshot inversion)

  • Posterior assumed Gaussian-around-MAP (LaplaceCovariance adapter)

StrongFourDVar — Strong-constraint 4DVar¶

Mathematical formulation¶

Control variable is the initial state x0\vect{x}_0x0​ alone; dynamics ftf_tft​ are treated as exact:

J(x0)=12∥x0−μx∥Σx−12+12∑t=0T∥yt−ht(ft(x0))∥Σε,t−12\mathcal{J}(\vect{x}_0) = \frac{1}{2} \Vert \vect{x}_0 - \gvect{\mu}_x \Vert^2_{\gmat{\Sigma}_x^{-1}} + \frac{1}{2} \sum_{t=0}^{T} \Vert \vect{y}_t - h_t(f_t(\vect{x}_0)) \Vert^2_{\gmat{\Sigma}_{\varepsilon,t}^{-1}}J(x0​)=21​∥x0​−μx​∥Σx−1​2​+21​t=0∑T​∥yt​−ht​(ft​(x0​))∥Σε,t−1​2​
(4)

Gradients of J\mathcal{J}J with respect to x0\vect{x}_0x0​ are computed by integrating the adjoint of ftf_tft​ backwards in time — vardax delegates this to diffrax.AbstractAdjoint (see Decision D15). The default RecursiveCheckpointAdjoint is autodiff with recursive checkpointing; BacksolveAdjoint solves the continuous adjoint ODE in reverse time (constant memory, good for long windows).

Class contract¶

When to use¶

  • Multi-timestep observations of a state with known dynamics

  • Model error is small enough to ignore

  • General-purpose 4DVar (use IncrementalFourDVar for the operational fast path)

WeakFourDVar — Weak-constraint 4DVar¶

Mathematical formulation¶

Control vector is augmented to include per-step model error:

η=(η1,…,ηT),xt=ftfree(xt−1)+ηt\gvect{\eta} = (\gvect{\eta}_1, \ldots, \gvect{\eta}_T), \quad \vect{x}_t = f_t^\text{free}(\vect{x}_{t-1}) + \gvect{\eta}_tη=(η1​,…,ηT​),xt​=ftfree​(xt−1​)+ηt​
(5)

with cost

J(x0,η)=12∥x0−μx∥Σx−12+12∑t∥yt−ht(xt)∥Σε,t−12+12∑t∥ηt∥Ση,t−12\mathcal{J}(\vect{x}_0, \gvect{\eta}) = \frac{1}{2} \Vert \vect{x}_0 - \gvect{\mu}_x \Vert^2_{\gmat{\Sigma}_x^{-1}} + \frac{1}{2} \sum_t \Vert \vect{y}_t - h_t(\vect{x}_t) \Vert^2_{\gmat{\Sigma}_{\varepsilon,t}^{-1}} + \frac{1}{2} \sum_t \Vert \gvect{\eta}_t \Vert^2_{\gmat{\Sigma}_{\eta,t}^{-1}}J(x0​,η)=21​∥x0​−μx​∥Σx−1​2​+21​t∑​∥yt​−ht​(xt​)∥Σε,t−1​2​+21​t∑​∥ηt​∥Ση,t−1​2​
(6)

The model-error covariance Ση,t\gmat{\Sigma}_{\eta,t}Ση,t​ is a separate input.

Class contract¶

When to use¶

  • Multi-timestep observations with non-negligible model error

  • Long assimilation windows where dynamics drift away from observations

  • Climatological or seasonal mismatch between ftfreef_t^\text{free}ftfree​ and reality

WeakFourDVar is computationally heavier than StrongFourDVar because the control vector dimension scales with TTT. Use sparingly; consider StrongFourDVar with a learned gaeg_\text{ae}gae​ as a cheaper alternative.

IncrementalFourDVar — Operational Fast Path¶

Mathematical formulation¶

Functionally equivalent to StrongFourDVar, but uses Gauss-Newton outer iterations on the full nonlinear cost with CG / Lanczos inner iterations on the linearised quadratic subproblem. At each outer iterate x(i)\vect{x}^{(i)}x(i) (with x(0)=μx\vect{x}^{(0)} = \gvect{\mu}_xx(0)=μx​; the background μx\gvect{\mu}_xμx​ stays fixed), linearise ftf_tft​ and hth_tht​ via jax.linearize:

δJ(δx)=12∥x(i)+δx−μx∥Σx−12+12∑t∥rt(i)−HtFt←0δx∥Σε,t−12\delta\mathcal{J}(\delta\vect{x}) = \frac{1}{2} \Vert \vect{x}^{(i)} + \delta\vect{x} - \gvect{\mu}_x \Vert^2_{\gmat{\Sigma}_x^{-1}} + \frac{1}{2} \sum_t \Vert \vect{r}_t^{(i)} - \mat{H}_t \mat{F}_{t \leftarrow 0} \delta\vect{x} \Vert^2_{\gmat{\Sigma}_{\varepsilon,t}^{-1}}δJ(δx)=21​∥x(i)+δx−μx​∥Σx−1​2​+21​t∑​∥rt(i)​−Ht​Ft←0​δx∥Σε,t−1​2​
(7)

with innovation rt(i)=yt−ht(ft(x(i)))\vect{r}_t^{(i)} = \vect{y}_t - h_t(f_t(\vect{x}^{(i)}))rt(i)​=yt​−ht​(ft​(x(i))). Solve HGNδx⋆=−∇J(x(i))\mat{H}_\text{GN} \delta\vect{x}^\star = -\nabla \mathcal{J}(\vect{x}^{(i)})HGN​δx⋆=−∇J(x(i)) by CG (the right-hand side keeps the background misfit −Σx−1(x(i)−μx)-\gmat{\Sigma}_x^{-1}(\vect{x}^{(i)} - \gvect{\mu}_x)−Σx−1​(x(i)−μx​)), update x(i+1)=x(i)+δx⋆\vect{x}^{(i+1)} = \vect{x}^{(i)} + \delta\vect{x}^\starx(i+1)=x(i)+δx⋆, relinearise.

Control-variable transform (CVT): set z=Lx−1δx\vect{z} = \mat{L}_x^{-1} \delta\vect{x}z=Lx−1​δx; the prior term becomes ∥z∥2\Vert \vect{z} \Vert^2∥z∥2 and the inner CG operates on a well-conditioned problem. Lx=Σx1/2\mat{L}_x = \gmat{\Sigma}_x^{1/2}Lx​=Σx1/2​ comes from gaussx.MaternLinearOperator.half().

Class contract¶

IncrementalConfig carries n_outer, n_inner, cg_atol, cg_rtol, cvt: bool (default True).

When to use¶

  • Operational 4DVar (ECMWF-style)

  • Long assimilation windows where general StrongFourDVar would be slow

  • When you want posterior covariance via Gauss-Newton Hessian without a separate adapter pass (the Hessian is already assembled in the last outer iteration)

FourDVarNet — Learned 4DVar¶

Mathematical formulation¶

Replace the Gaussian prior ∥x−μx∥Σx−12\Vert \vect{x} - \gvect{\mu}_x \Vert^2_{\gmat{\Sigma}_x^{-1}}∥x−μx​∥Σx−1​2​ with a learned prior ∥x−gae(x;θ)∥2\Vert \vect{x} - g_\text{ae}(\vect{x}; \gvect{\theta}) \Vert^2∥x−gae​(x;θ)∥2, where gaeg_\text{ae}gae​ is an autoencoder (BilinAE, ConvAE, MLPAE). Replace the standard gradient-descent inner solver with a learned gradient modulator gmodg_\text{mod}gmod​:

x(i+1)=x(i)−gmod(∇xJ(x(i)),c(i))\vect{x}^{(i+1)} = \vect{x}^{(i)} - g_\text{mod}(\nabla_{\vect{x}} \mathcal{J}(\vect{x}^{(i)}), \vect{c}^{(i)})x(i+1)=x(i)−gmod​(∇x​J(x(i)),c(i))
(8)

with J(x)=αobs∥h(x)−y∥2+αprior∥x−gae(x;θ)∥2\mathcal{J}(\vect{x}) = \alpha_\text{obs} \Vert h(\vect{x}) - \vect{y} \Vert^2 + \alpha_\text{prior} \Vert \vect{x} - g_\text{ae}(\vect{x}; \gvect{\theta}) \Vert^2J(x)=αobs​∥h(x)−y∥2+αprior​∥x−gae​(x;θ)∥2.

Training minimises reconstruction MSE against ground truth:

L(θ,θmod)=∥x⋆(θ,θmod)−xtrue∥2.\mathcal{L}(\gvect{\theta}, \gvect{\theta}_\text{mod}) = \Vert \vect{x}^\star(\gvect{\theta}, \gvect{\theta}_\text{mod}) - \vect{x}_\text{true} \Vert^2.L(θ,θmod​)=∥x⋆(θ,θmod​)−xtrue​∥2.
(9)

The training gradient ∇θ,θmodL\nabla_{\gvect{\theta}, \gvect{\theta}_\text{mod}} \mathcal{L}∇θ,θmod​​L flows through the inner solver via the solver_adjoint slot (an optimistix.AbstractAdjoint).

When to use¶

  • Research / benchmarks where ground-truth xtrue\vect{x}_\text{true}xtrue​ is available for training

  • Data-rich regimes (the learned gaeg_\text{ae}gae​ shines)

AmortizedPosterior — Direct head¶

Mathematical formulation¶

Learn a conditional density q(x∣y;ν)q(\vect{x} \mid \vect{y}; \gvect{\nu})q(x∣y;ν) that approximates p(x∣y)p(\vect{x} \mid \vect{y})p(x∣y). Train on simulated pairs from the prior and forward:

ν⋆=argminνE(x,y)∼p(x,y)KL(q(⋅∣y;ν)∥p(⋅∣y)).\gvect{\nu}^\star = \underset{\gvect{\nu}}{\op{argmin}} \mathbb{E}_{(\vect{x}, \vect{y}) \sim p(\vect{x}, \vect{y})} \mathrm{KL}\left(q(\cdot \mid \vect{y}; \gvect{\nu}) \Vert p(\cdot \mid \vect{y})\right).ν⋆=νargmin​E(x,y)∼p(x,y)​KL(q(⋅∣y;ν)∥p(⋅∣y)).
(10)

Head variants: conditional normalising flow (gauss_flows), score-based diffusion, regression (Gaussian heads).

Class contract¶

When to use¶

  • Real-time inference (single forward pass, sub-second)

  • Many independent events (catalog reprocessing)

  • After validating against a StrongFourDVar / IncrementalFourDVar oracle on a held-out set (six-step cycle gates, Decision D12)

AnalysisStep adapter (Decision D8)¶

All seven classes expose .as_analysis_step():

The adapter shells the model’s __call__ to match the pipekit-cycle analysis signature. The OptimalInterpolation and ThreeDVar adapters analyse around forecast (the background μx\gvect{\mu}_xμx​, not the model’s prior_mean) and use the cycle’s obs_op and obs_err_cov (hhh and Σε\gmat{\Sigma}_\varepsilonΣε​; None falls back to the model’s own), keeping the model’s Σx\gmat{\Sigma}_xΣx​. Use it in pipekit_cycle.DACycle:

The same pipeline accepts OptimalInterpolation, ThreeDVar, StrongFourDVar, WeakFourDVar, IncrementalFourDVar, FourDVarNet, or AmortizedPosterior — what changes is the inference algorithm, not the orchestration code.

Linear-Gaussian baseline (Decision D14 invariant)¶

In the linear-Gaussian limit (linear hhh, Gaussian Σx\gmat{\Sigma}_xΣx​ and Σε\gmat{\Sigma}_\varepsilonΣε​), all seven methods must agree:

OptimalInterpolation(batch)
  ≈ ThreeDVar(batch)                                # iterative GN
  ≈ StrongFourDVar(batch)         (T = 0)
  ≈ WeakFourDVar(batch)           (T = 0, η = 0)
  ≈ IncrementalFourDVar(batch)    (T = 0)
  ≈ FourDVarNet(batch)            (IdentityPrior, n_steps large)
  ≈ AmortizedPosterior(batch)     (trained to convergence on this regime)

tests/test_linear_gaussian_agreement.py enforces this — it is the canonical correctness baseline. If a new analysis method disagrees with OptimalInterpolation in the linear-Gaussian limit, something is wrong.

Training utilities¶

train_step and eval_step¶

Library code (Decision D5) — encode correct differentiation through whichever inner algorithm the model uses (4DVarNet inner solver, amortized head, …):

Only FourDVarNet and AmortizedPosterior have learned parameters and therefore use train_step / eval_step. The classical methods are non-learnable — there are no parameters to optimise over (the prior covariance Σx\gmat{\Sigma}_xΣx​ is supplied, not learned).
