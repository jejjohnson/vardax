3DVar (3D Variational)

When the observation operator hhh is nonlinear, the closed-form OI analysis (4.4) of chapter 4 no longer applies, because the posterior is no longer Gaussian. 3DVar gives up the closed form, keeps the Gaussian prior, and computes the MAP estimate (1.2) iteratively.

Cost function¶

For a Gaussian prior and likelihood the MAP estimate minimises

J(x)=12∥x−μx∥Σx−12+12∥y−h(x)∥Σε−12\mathcal{J}(\vect{x}) = \frac{1}{2} \Vert \vect{x} - \gvect{\mu}_x \Vert^2_{\gmat{\Sigma}_x^{-1}} + \frac{1}{2} \Vert \vect{y} - h(\vect{x}) \Vert^2_{\gmat{\Sigma}_\varepsilon^{-1}}J(x)=21​∥x−μx​∥Σx−1​2​+21​∥y−h(x)∥Σε−1​2​
(5.1)

That term is small near the MAP when the residual y−h(x)\vect{y} - h(\vect{x})y−h(x) is small, and without it the Hessian is positive-definite, so CG can solve with it.

The single time¶

“3D” refers to the three spatial dimensions of the state; T=0T = 0T=0 in the 4D notation of chapter 1, so there are no dynamics, only one observation set and one inversion.

This is the right regime for:

  • Snapshot inversions (single satellite overpass, single sounding)

  • Static fields (long-term mean, climatology)

  • Multi-instrument fusion at a single time

  • Methane source attribution from a single overpass (chapter 17)

It prints background error 0.76, analysis error 0.40 and converged True in 63 steps.

The minimiser is any optimistix.AbstractMinimiser, or a vardax Minimiser such as OptaxMinimiser; the choice depends on the cost function’s geometry:

MinimiserWhen
optx.BFGS(...)General-purpose; no special structure required (the default)
optx.NonlinearCG(...)Memory-constrained; many parameters
optx.NelderMead(...)Derivative-free; the cost has kinks

optx.GaussNewton and optx.LevenbergMarquardt are least-squares solvers, not minimisers, so ThreeDVar rejects them; the Gauss-Newton fast path is IncrementalFourDVar (chapter 8).

The minimiser_adjoint controls how gradients flow through the minimiser if the model is itself differentiated through (e.g., for training hyperparameters of Σx\gmat{\Sigma}_xΣx​). ImplicitAdjoint is the default; it uses the implicit function theorem at the optimum (12.2), which gives exact gradients with O(1)O(1)O(1) memory. The 4DVar models take the same minimiser= and minimiser_adjoint= slots, and chapter 6 adds a first-order minimiser for large controls.

Algorithm¶

Written out, (5.1) is two whitened quadratic forms, one per term, each applied with a CG solve rather than an inverse. ThreeDVar builds the same cost, with the residual masked where observations are missing (the mask here is all ones), and hands it to optimistix.minimise.

Convergence is typically tens of iterations for well-conditioned problems. The optimistix machinery handles step size, line search, and termination criteria internally.

When 3DVar is the right answer¶

Use ThreeDVar when hhh is nonlinear (averaging kernel, RTM, custom retrieval), there is a single time (the regimes listed above), Σx\gmat{\Sigma}_xΣx​ and Σε\gmat{\Sigma}_\varepsilonΣε​ are Gaussian, and a Gaussian around the MAP describes the posterior. If any of these fail:

  • Linear hhh: OptimalInterpolation (chapter 4) gives the same answer with an exact posterior.

  • Dynamics: StrongFourDVar (chapter 6).

  • Multimodal posterior: the ensemble or amortized methods of the posterior section above.

When the minimiser fails to converge¶

If the minimiser fails (the cost stops decreasing, or the line search rejects every step), the likely causes are:

  • The cost is far from quadratic: switch from NonlinearCG to BFGS, or relinearise with IncrementalFourDVar (chapter 8) for a 4DVar window.

  • The prior is too tight (small variance) but biased: widen Σx\gmat{\Sigma}_xΣx​ or check μx\gvect{\mu}_xμx​ against innovation statistics.

  • The observation operator has discontinuities or near-discontinuities (saturated retrievals, mask edges): smooth them in preprocessing or switch to the derivative-free optimistix.NelderMead.

  • A linear solve inside the cost returns NaN (“A linear solver returned non-finite output”). The cost applies Σx−1\gmat{\Sigma}_x^{-1}Σx−1​ and Σε−1\gmat{\Sigma}_\varepsilon^{-1}Σε−1​ with lx.CG(atol=1e-6, rtol=1e-6) by default, which breaks down on an ill-conditioned or tiny covariance (a Σε\gmat{\Sigma}_\varepsilonΣε​ of 10−14I10^{-14} \mat{I}10−14I, say). Pass cov_solver=lx.AutoLinearSolver(well_posed=True) (or lx.Cholesky()) when the operators can be materialised, or rescale the problem so the covariances are O(1)O(1)O(1). The 4DVar models take the same cov_solver=.

vardax does not retry or fall back automatically, because a failed minimisation is information to diagnose rather than hide. model.analyse(batch) returns the analysis together with a MinimiseResult per sample: the cost and gradient norm at the minimum, the number of steps taken, and converged, the minimiser’s own verdict (optimistix’s result == successful). Read converged rather than comparing num_steps with max_steps: a line search that gives up stops early without converging, and a tolerance can be met on the last allowed step.
