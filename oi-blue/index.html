Optimal Interpolation / BLUE

For linear-Gaussian state estimation, the posterior is Gaussian in closed form and the analysis is a single matrix expression. This is the Best Linear Unbiased Estimator (BLUE), known in geosciences as Optimal Interpolation (OI). It is the first method you should reach for when the regime allows it (Decision D16).

Setup¶

The prior is

p(x)=N(x;μx,Σx), with x∈RDxp(\vect{x}) = \mathcal{N}(\vect{x}; \gvect{\mu}_x, \gmat{\Sigma}_x), \text{ with } \vect{x} \in \mathbb{R}^{D_x}p(x)=N(x;μx​,Σx​), with x∈RDx​
(4.1)

where μx\gvect{\mu}_xμx​ is the background mean and Σx\gmat{\Sigma}_xΣx​ the background-error covariance. The likelihood is the observation model (2.1) with a linear H\mat{H}H,

p(y∣x)=N(y;Hx,Σε), with y∈RDy and H∈RDy×Dxp(\vect{y} \mid \vect{x}) = \mathcal{N}(\vect{y}; \mat{H} \vect{x}, \gmat{\Sigma}_\varepsilon), \text{ with } \vect{y} \in \mathbb{R}^{D_y} \text{ and } \mat{H} \in \mathbb{R}^{D_y \times D_x}p(y∣x)=N(y;Hx,Σε​), with y∈RDy​ and H∈RDy​×Dx​
(4.2)

where Σε\gmat{\Sigma}_\varepsilonΣε​ is the observation-error covariance. By the standard Gaussian conjugacy result, the posterior is

p(x∣y)=N(x;x⋆,Σx∣y)p(\vect{x} \mid \vect{y}) = \mathcal{N}(\vect{x}; \vect{x}^\star, \gmat{\Sigma}_{x \mid y})p(x∣y)=N(x;x⋆,Σx∣y​)
(4.3)

with mean

x⋆=μx+G(y−Hμx), with G=ΣxH⊤(HΣxH⊤+Σε)−1\vect{x}^\star = \gvect{\mu}_x + \mat{G}(\vect{y} - \mat{H} \gvect{\mu}_x), \text{ with } \mat{G} = \gmat{\Sigma}_x \mat{H}^\top (\mat{H} \gmat{\Sigma}_x \mat{H}^\top + \gmat{\Sigma}_\varepsilon)^{-1}x⋆=μx​+G(y−Hμx​), with G=Σx​H⊤(HΣx​H⊤+Σε​)−1
(4.4)

where G\mat{G}G is the Kalman gain and y−Hμx\vect{y} - \mat{H} \gvect{\mu}_xy−Hμx​ the innovation, and covariance

Σx∣y=(I−GH)Σx=(Σx−1+H⊤Σε−1H)−1\gmat{\Sigma}_{x \mid y} = (\mat{I} - \mat{G} \mat{H}) \gmat{\Sigma}_x = (\gmat{\Sigma}_x^{-1} + \mat{H}^\top \gmat{\Sigma}_\varepsilon^{-1} \mat{H})^{-1}Σx∣y​=(I−GH)Σx​=(Σx−1​+H⊤Σε−1​H)−1
(4.5)

The shapes are x,μx,x⋆∈RDx\vect{x}, \gvect{\mu}_x, \vect{x}^\star \in \mathbb{R}^{D_x}x,μx​,x⋆∈RDx​, y∈RDy\vect{y} \in \mathbb{R}^{D_y}y∈RDy​, Σx,Σx∣y∈RDx×Dx\gmat{\Sigma}_x, \gmat{\Sigma}_{x \mid y} \in \mathbb{R}^{D_x \times D_x}Σx​,Σx∣y​∈RDx​×Dx​, Σε∈RDy×Dy\gmat{\Sigma}_\varepsilon \in \mathbb{R}^{D_y \times D_y}Σε​∈RDy​×Dy​ and G∈RDx×Dy\mat{G} \in \mathbb{R}^{D_x \times D_y}G∈RDx​×Dy​.

The two forms of Σx∣y\gmat{\Sigma}_{x \mid y}Σx∣y​ are equivalent by Sherman-Morrison-Woodbury, and which one to compute depends on which is cheaper.

Two equivalent expressions, two computations¶

The Kalman gain in (4.4) requires inverting a Dy×DyD_y \times D_yDy​×Dy​ matrix (observation-space form). The second form of (4.5) instead inverts the posterior precision Σx−1+H⊤Σε−1H\gmat{\Sigma}_x^{-1} + \mat{H}^\top \gmat{\Sigma}_\varepsilon^{-1} \mat{H}Σx−1​+H⊤Σε−1​H, a Dx×DxD_x \times D_xDx​×Dx​ matrix (state-space form).

Pick the form whose matrix is smaller:

RegimeFormInversion size
Dy≪DxD_y \ll D_xDy​≪Dx​ (sparse observations)Kalman gain G\mat{G}G of (4.4)Dy×DyD_y \times D_yDy​×Dy​
Dy≫DxD_y \gg D_xDy​≫Dx​ (dense observations)precision Σx∣y−1\gmat{\Sigma}_{x \mid y}^{-1}Σx∣y−1​ of (4.5)Dx×DxD_x \times D_xDx​×Dx​

For SSH altimetry with sparse along-track samples and a 2D grid, Dy≪DxD_y \ll D_xDy​≪Dx​ and the observation-space form wins. For a satellite imager with one observation per state cell, Dy≈DxD_y \approx D_xDy​≈Dx​ and either works.

OptimalInterpolation solves the observation-space system (HΣxH⊤+Σε)v=y−Hμx(\mat{H} \gmat{\Sigma}_x \mat{H}^\top + \gmat{\Sigma}_\varepsilon) \vect{v} = \vect{y} - \mat{H} \gvect{\mu}_x(HΣx​H⊤+Σε​)v=y−Hμx​ by default, and the state-space system (Σx−1+H⊤Σε−1H)δx=H⊤Σε−1(y−Hμx)(\gmat{\Sigma}_x^{-1} + \mat{H}^\top \gmat{\Sigma}_\varepsilon^{-1} \mat{H}) \delta\vect{x} = \mat{H}^\top \gmat{\Sigma}_\varepsilon^{-1} (\vect{y} - \mat{H} \gvect{\mu}_x)(Σx−1​+H⊤Σε−1​H)δx=H⊤Σε−1​(y−Hμx​) with form="state". The block below fuses Dy=2000D_y = 2000Dy​=2000 pixels into Dx=3D_x = 3Dx​=3 unknowns and prints True: both forms give the same analysis.

The observation-space solve factors a 2000×20002000 \times 20002000×2000 matrix here, the state-space one a 3×33 \times 33×3 matrix.

Why the matrices are never materialised¶

Both forms require solving a linear system, not inverting a matrix explicitly. kernellib and gaussx supply structured operators:

  • Σx\gmat{\Sigma}_xΣx​ as a Matérn covariance: kernellib.ImplicitKernelOperator(matern, coords) applies it matrix-free with O(Dx)O(D_x)O(Dx​) memory, and gaussx.Kronecker exploits separable grids. Both can be passed to a vardax model directly when the state is a single (Dx,)(D_x,)(Dx​,) vector; for a (T+1,Dx)(T + 1, D_x)(T+1,Dx​) state, wrap the mat-vec as lx.FunctionLinearOperator(apply, structure, lx.positive_semidefinite_tag), as the example below does.

  • Σε\gmat{\Sigma}_\varepsilonΣε​ as lineax.DiagonalLinearOperator(variances), which is diagonal and trivial.

  • HΣxH⊤\mat{H} \gmat{\Sigma}_x \mat{H}^\topHΣx​H⊤ is never materialised; only v↦HΣxH⊤v\vect{v} \mapsto \mat{H} \gmat{\Sigma}_x \mat{H}^\top \vect{v}v↦HΣx​H⊤v is needed, which is one mat-vec each with H⊤\mat{H}^\topH⊤, Σx\gmat{\Sigma}_xΣx​ and H\mat{H}H.

The innovation system (HΣxH⊤+Σε)v=y−Hμx(\mat{H} \gmat{\Sigma}_x \mat{H}^\top + \gmat{\Sigma}_\varepsilon) \vect{v} = \vect{y} - \mat{H} \gvect{\mu}_x(HΣx​H⊤+Σε​)v=y−Hμx​ is then solved by lineax.CG, returning v∈RDy\vect{v} \in \mathbb{R}^{D_y}v∈RDy​ in O(Niter⋅Dy)O(N_\text{iter} \cdot D_y)O(Niter​⋅Dy​) time where NiterN_\text{iter}Niter​ is the CG iteration count (typically tens). The analysis (4.4) is then x⋆=μx+ΣxH⊤v\vect{x}^\star = \gvect{\mu}_x + \gmat{\Sigma}_x \mat{H}^\top \vect{v}x⋆=μx​+Σx​H⊤v, one more mat-vec.

CG runs at a fixed tolerance with a step cap, so its analysis is approximate, and an ill-conditioned HΣxH⊤+Σε\mat{H} \gmat{\Sigma}_x \mat{H}^\top + \gmat{\Sigma}_\varepsilonHΣx​H⊤+Σε​ (small Σε\gmat{\Sigma}_\varepsilonΣε​, smooth Σx\gmat{\Sigma}_xΣx​) can exhaust the cap. When the innovation system is small enough to factor, pass a direct solver instead: OptimalInterpolation(..., solver=lx.Cholesky()) (or lx.AutoLinearSolver(well_posed=True)) gives the BLUE to machine precision, and posterior() then uses the same solver for its covariance.

A full OI on a 2D Matérn prior with 50,000 grid cells and 5,000 observations takes seconds on a single GPU. No materialised matrices, no O(Dx3)O(D_x^3)O(Dx3​) factorisations.

Implementation in vardax¶

The example is a toy along-track problem: Dx=20D_x = 20Dx​=20 cells every 10 km on one track, Dy=5D_y = 5Dy​=5 samples, a Matérn-3/2 prior Σx\gmat{\Sigma}_xΣx​ with length scale ℓ=50\ell = 50ℓ=50 km and standard deviation σx=0.1\sigma_x = 0.1σx​=0.1 m around a zero climatology, and Σε=σε2I\gmat{\Sigma}_\varepsilon = \sigma_\varepsilon^2 \mat{I}Σε​=σε2​I with σε=0.02\sigma_\varepsilon = 0.02σε​=0.02 m. The truth is a smooth sine wave and the observations add noise to it. The window has T=0T = 0T=0 steps, so the state has shape (T+1,Dx)=(1,Dx)(T + 1, D_x) = (1, D_x)(T+1,Dx​)=(1,Dx​), as posterior expects.

It prints background error 0.316, analysis error 0.095 and posterior std 0.019 observed, 0.035 in a gap. The Cholesky solver makes the analysis and the posterior exact; the posterior solves the same innovation system as the analysis and never applies Σx−1\gmat{\Sigma}_x^{-1}Σx−1​.

The posterior.cov is an AbstractLinearOperator representing Σx∣y\gmat{\Sigma}_{x \mid y}Σx∣y​. Sampling from the posterior is a mat-vec in Σx∣y1/2\gmat{\Sigma}_{x \mid y}^{1/2}Σx∣y1/2​; the diagonal of Σx∣y\gmat{\Sigma}_{x \mid y}Σx∣y​ (marginal variances) is one more mat-vec family. Nothing is ever materialised.

Validation¶

OptimalInterpolation is the canonical baseline. Every more sophisticated method must agree with it in the linear-Gaussian limit (Decision D14 invariant). tests/test_linear_gaussian_agreement.py enforces this for ThreeDVar, StrongFourDVar, WeakFourDVar and IncrementalFourDVar. The block below checks the first two against the BLUE, with fff the identity and a single time for StrongFourDVar. It prints True twice. Both use a direct cov_solver and 500 minimiser steps, because the smooth prior makes Σx−1\gmat{\Sigma}_x^{-1}Σx−1​ ill-conditioned and BFGS needs about 260 steps here.

If a new method disagrees with OptimalInterpolation in this limit, something is wrong. The agreement is the definition of correctness.

Connection to the Kalman filter¶

The Kalman filter analysis step is OI applied at each cycle,

forecast: xt∣t−1=Ftxt−1∣t−1, and Σx,t∣t−1=FtΣx,t−1∣t−1Ft⊤+Σηanalysis: Gt=Σx,t∣t−1H⊤(HΣx,t∣t−1H⊤+Σε)−1xt∣t=xt∣t−1+Gt(yt−Hxt∣t−1)Σx,t∣t=(I−GtH)Σx,t∣t−1\begin{aligned} \text{forecast: } & \vect{x}_{t \mid t-1} = \mat{F}_t \vect{x}_{t-1 \mid t-1}, \text{ and } \gmat{\Sigma}_{x,t \mid t-1} = \mat{F}_t \gmat{\Sigma}_{x,t-1 \mid t-1} \mat{F}_t^\top + \gmat{\Sigma}_\eta \\ \text{analysis: } & \mat{G}_t = \gmat{\Sigma}_{x,t \mid t-1} \mat{H}^\top (\mat{H} \gmat{\Sigma}_{x,t \mid t-1} \mat{H}^\top + \gmat{\Sigma}_\varepsilon)^{-1} \\ & \vect{x}_{t \mid t} = \vect{x}_{t \mid t-1} + \mat{G}_t (\vect{y}_t - \mat{H} \vect{x}_{t \mid t-1}) \\ & \gmat{\Sigma}_{x,t \mid t} = (\mat{I} - \mat{G}_t \mat{H}) \gmat{\Sigma}_{x,t \mid t-1} \end{aligned}forecast: analysis: ​xt∣t−1​=Ft​xt−1∣t−1​, and Σx,t∣t−1​=Ft​Σx,t−1∣t−1​Ft⊤​+Ση​Gt​=Σx,t∣t−1​H⊤(HΣx,t∣t−1​H⊤+Σε​)−1xt∣t​=xt∣t−1​+Gt​(yt​−Hxt∣t−1​)Σx,t∣t​=(I−Gt​H)Σx,t∣t−1​​
(4.6)

where xt∣t−1∈RDx\vect{x}_{t \mid t-1} \in \mathbb{R}^{D_x}xt∣t−1​∈RDx​ and Σx,t∣t−1∈RDx×Dx\gmat{\Sigma}_{x,t \mid t-1} \in \mathbb{R}^{D_x \times D_x}Σx,t∣t−1​∈RDx​×Dx​ are the forecast mean and covariance, xt∣t\vect{x}_{t \mid t}xt∣t​ and Σx,t∣t\gmat{\Sigma}_{x,t \mid t}Σx,t∣t​ the analysis mean and covariance, Ft∈RDx×Dx\mat{F}_t \in \mathbb{R}^{D_x \times D_x}Ft​∈RDx​×Dx​ the linear dynamics, Ση∈RDx×Dx\gmat{\Sigma}_\eta \in \mathbb{R}^{D_x \times D_x}Ση​∈RDx​×Dx​ the model-error covariance and Gt∈RDx×Dy\mat{G}_t \in \mathbb{R}^{D_x \times D_y}Gt​∈RDx​×Dy​ the gain. The analysis lines are (4.4) and the first form of (4.5).

The analysis step is exactly OptimalInterpolation with prior_mean set to xt∣t−1\vect{x}_{t \mid t-1}xt∣t−1​, prior_cov_op to Σx,t∣t−1\gmat{\Sigma}_{x,t \mid t-1}Σx,t∣t−1​, obs_cov_op to Σε\gmat{\Sigma}_\varepsilonΣε​ and obs_op to H\mat{H}H. The forecast step lives in filterax (it’s about propagating uncertainty through dynamics, not about inference per se).

This means filterax’s Kalman filter can be built compositionally: forecast via filterax, analysis via vardax OptimalInterpolation, update covariance via filterax. The interfaces line up because both libraries respect the same protocols.

For a linear-Gaussian state-space model, filterax.KalmanSmoother runs the whole recursion exactly: the filter above, then the Rauch–Tung–Striebel smoother backwards, over irregular observation times, with KalmanSmoother.from_sde building the transitions from a gaussx SDE kernel.

When OI is the right answer¶

Use OptimalInterpolation when all of:

  • hhh is linear (or the linearisation around μx\gvect{\mu}_xμx​ is good enough that the residual nonlinearity is dominated by observation noise)

  • Σx\gmat{\Sigma}_xΣx​ and Σε\gmat{\Sigma}_\varepsilonΣε​ are Gaussian

  • The posterior is unimodal (no symmetry-breaking, no bistable regimes)

  • A single timestep (no dynamics) or the dynamics are linear

If any fails:

  • Nonlinear hhh → ThreeDVar (chapter 5)

  • Dynamics → StrongFourDVar / IncrementalFourDVar (chapters 6, 8)

  • Non-Gaussian likelihood → AmortizedPosterior with score head (chapter 10)

  • Multimodal posterior → ensemble methods via filterax

OptimalInterpolation does not check that obs_op is linear: it linearises a nonlinear operator at μx\gvect{\mu}_xμx​ and returns a single extended-Kalman update, so a nonlinear hhh belongs in ThreeDVar.
