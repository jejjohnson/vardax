Optimal Interpolation / BLUE

For linear-Gaussian state estimation, the posterior is Gaussian in closed form and the analysis is a single matrix expression. This is the Best Linear Unbiased Estimator (BLUE), known in geosciences as Optimal Interpolation (OI). It is the first method you should reach for when the regime allows it (Decision D16).

Setup¶

The prior is

p(x)=N(x;xb,B), with x∈Rnp(x) = \mathcal{N}(x; x_b, B), \text{ with } x \in \mathbb{R}^np(x)=N(x;xb​,B), with x∈Rn
(4.1)

where xbx_bxb​ is the background mean and BBB the background-error covariance. The likelihood is the observation model (2.1) with a linear HHH,

p(y∣x)=N(y;Hx,R), with H∈Rm×np(y \mid x) = \mathcal{N}(y; H x, R), \text{ with } H \in \mathbb{R}^{m \times n}p(y∣x)=N(y;Hx,R), with H∈Rm×n
(4.2)

where RRR is the observation-error covariance. By the standard Gaussian conjugacy result, the posterior is

p(x∣y)=N(x;x∗,P∗)p(x \mid y) = \mathcal{N}(x; x^*, P^*)p(x∣y)=N(x;x∗,P∗)
(4.3)

with mean

x∗=xb+K(y−Hxb), with K=BH⊤(HBH⊤+R)−1x^* = x_b + K(y - H x_b), \text{ with } K = B H^\top (H B H^\top + R)^{-1}x∗=xb​+K(y−Hxb​), with K=BH⊤(HBH⊤+R)−1
(4.4)

where KKK is the Kalman gain and y−Hxby - H x_by−Hxb​ the innovation, and covariance

P∗=(I−KH)B=(B−1+H⊤R−1H)−1P^* = (I - K H) B = (B^{-1} + H^\top R^{-1} H)^{-1}P∗=(I−KH)B=(B−1+H⊤R−1H)−1
(4.5)

The two forms of P∗P^*P∗ are equivalent by Sherman-Morrison-Woodbury, and which one to compute depends on which is cheaper.

Two equivalent expressions, two computations¶

The Kalman gain in (4.4) requires inverting an m×mm \times mm×m matrix (observation-space form). The second form of (4.5) instead inverts the posterior precision B−1+H⊤R−1HB^{-1} + H^\top R^{-1} HB−1+H⊤R−1H, an n×nn \times nn×n matrix (state-space form).

Pick the form whose matrix is smaller:

RegimeFormInversion size
m≪nm \ll nm≪n (sparse observations)Kalman gain KKK of (4.4)m×mm \times mm×m
m≫nm \gg nm≫n (dense observations)precision (P∗)−1(P^*)^{-1}(P∗)−1 of (4.5)n×nn \times nn×n

For SSH altimetry with sparse along-track samples and a 2D grid, m≪nm \ll nm≪n and the observation-space form wins. For a satellite imager with one observation per state cell, m≈nm \approx nm≈n and either works.

OptimalInterpolation solves the observation-space system (HBH⊤+R)v=y−Hxb(H B H^\top + R) v = y - H x_b(HBH⊤+R)v=y−Hxb​ by default, and the state-space system (B−1+H⊤R−1H)δx=H⊤R−1(y−Hxb)(B^{-1} + H^\top R^{-1} H) \delta x = H^\top R^{-1} (y - H x_b)(B−1+H⊤R−1H)δx=H⊤R−1(y−Hxb​) with form="state". The block below fuses m=2000m = 2000m=2000 pixels into n=3n = 3n=3 unknowns and prints True: both forms give the same analysis.

The observation-space solve factors a 2000×20002000 \times 20002000×2000 matrix here, the state-space one a 3×33 \times 33×3 matrix.

Why the matrices are never materialised¶

Both forms require solving a linear system, not inverting a matrix explicitly. kernellib and gaussx supply structured operators:

  • BBB as a Matérn covariance: kernellib.ImplicitKernelOperator(matern, coords) applies it matrix-free with O(N)O(N)O(N) memory, and gaussx.Kronecker exploits separable grids. Both can be passed to a vardax model directly when the state is a single (N,)(N,)(N,) vector; for a (T,N)(T, N)(T,N) state, wrap the mat-vec as lx.FunctionLinearOperator(apply, structure, lx.positive_semidefinite_tag), as the example below does.

  • RRR as lineax.DiagonalLinearOperator(variances), which is diagonal and trivial.

  • HBH⊤H B H^\topHBH⊤ is never materialised; only v↦HBH⊤vv \mapsto H B H^\top vv↦HBH⊤v is needed, which is one mat-vec each with H⊤H^\topH⊤, BBB and HHH.

The innovation system (HBH⊤+R)v=y−Hxb(H B H^\top + R) v = y - H x_b(HBH⊤+R)v=y−Hxb​ is then solved by lineax.CG, returning vvv in O(k⋅m)O(k \cdot m)O(k⋅m) time where kkk is the CG iteration count (typically tens). The analysis (4.4) is then x∗=xb+BH⊤vx^* = x_b + B H^\top vx∗=xb​+BH⊤v, one more mat-vec.

CG runs at a fixed tolerance with a step cap, so its analysis is approximate, and an ill-conditioned HBH⊤+RH B H^\top + RHBH⊤+R (small RRR, smooth BBB) can exhaust the cap. When the innovation system is small enough to factor, pass a direct solver instead: OptimalInterpolation(..., solver=lx.Cholesky()) (or lx.AutoLinearSolver(well_posed=True)) gives the BLUE to machine precision, and posterior() then uses the same solver for its covariance.

A full OI on a 2D Matérn prior with 50,000 grid cells and 5,000 observations takes seconds on a single GPU. No materialised matrices, no O(n3)O(n^3)O(n3) factorisations.

Implementation in vardax¶

The example is a toy along-track problem: N=20N = 20N=20 cells every 10 km on one track, M=5M = 5M=5 samples, a Matérn-3/2 prior BBB with length scale ℓ=50\ell = 50ℓ=50 km and standard deviation σb=0.1\sigma_b = 0.1σb​=0.1 m around a zero climatology, and R=σo2IR = \sigma_o^2 IR=σo2​I with σo=0.02\sigma_o = 0.02σo​=0.02 m. The truth is a smooth sine wave and the observations add noise to it. The state has shape (T,N)(T, N)(T,N) with T=1T = 1T=1, as posterior expects.

It prints background error 0.316, analysis error 0.095 and posterior std 0.019 observed, 0.035 in a gap. The Cholesky solver makes the analysis and the posterior exact; the posterior solves the same innovation system as the analysis and never applies B−1B^{-1}B−1.

The posterior.cov is an AbstractLinearOperator representing P∗P^*P∗. Sampling from the posterior is a mat-vec in (P∗)1/2(P^*)^{1/2}(P∗)1/2; the diagonal of P∗P^*P∗ (marginal variances) is one more mat-vec family. Nothing is ever materialised.

Validation¶

OptimalInterpolation is the canonical baseline. Every more sophisticated method must agree with it in the linear-Gaussian limit (Decision D14 invariant). tests/test_linear_gaussian_agreement.py enforces this for ThreeDVar, StrongFourDVar, WeakFourDVar and IncrementalFourDVar. The block below checks the first two against the BLUE, with MtM_tMt​ the identity and a single time for StrongFourDVar. It prints True twice. Both use a direct cov_solver and 500 minimiser steps, because the smooth prior makes B−1B^{-1}B−1 ill-conditioned and BFGS needs about 260 steps here.

If a new method disagrees with OptimalInterpolation in this limit, something is wrong. The agreement is the definition of correctness.

Connection to the Kalman filter¶

The Kalman filter analysis step is OI applied at each cycle,

forecast: xtf=Mtxt−1a, and Ptf=MtPt−1aMt⊤+Qanalysis: Kt=PtfH⊤(HPtfH⊤+R)−1xta=xtf+Kt(yt−Hxtf)Pta=(I−KtH)Ptf\begin{aligned} \text{forecast: } & x^f_t = M_t x^a_{t-1}, \text{ and } P^f_t = M_t P^a_{t-1} M_t^\top + Q \\ \text{analysis: } & K_t = P^f_t H^\top (H P^f_t H^\top + R)^{-1} \\ & x^a_t = x^f_t + K_t (y_t - H x^f_t) \\ & P^a_t = (I - K_t H) P^f_t \end{aligned}forecast: analysis: ​xtf​=Mt​xt−1a​, and Ptf​=Mt​Pt−1a​Mt⊤​+QKt​=Ptf​H⊤(HPtf​H⊤+R)−1xta​=xtf​+Kt​(yt​−Hxtf​)Pta​=(I−Kt​H)Ptf​​
(4.6)

where xtfx^f_txtf​ and PtfP^f_tPtf​ are the forecast mean and covariance, xtax^a_txta​ and PtaP^a_tPta​ the analysis mean and covariance, MtM_tMt​ the linear dynamics and QQQ the model-error covariance. The analysis lines are (4.4) and the first form of (4.5).

The analysis step is exactly OptimalInterpolation(prior_mean=x^f_t, prior_cov_op=P^f_t, obs_cov_op=R, obs_op=H).

For a linear-Gaussian state-space model, KalmanSmoother runs the whole recursion exactly: the filter above, then the Rauch–Tung–Striebel smoother backwards, so each xtx_txt​ is conditioned on every observation in the window. Its transitions act over the actual gaps between observation times, so irregular times need no regridding, and KalmanSmoother.from_sde builds them from a gaussx SDE kernel. The block below smooths an Ornstein–Uhlenbeck process observed at four irregular times, the third missing, and prints the smoothed means.

It prints 0.93 0.76 -0.08 -0.17: the missing third time is filled from its neighbours, pulled towards the close fourth observation.

The forecast step of an ensemble or nonlinear filter lives in filterax, which composes with OptimalInterpolation for the analysis in the same way.

When OI is the right answer¶

Use OptimalInterpolation when all of:

  • HHH is linear (or the linearisation around xbx_bxb​ is good enough that the residual nonlinearity is dominated by observation noise)

  • BBB and RRR are Gaussian

  • The posterior is unimodal (no symmetry-breaking, no bistable regimes)

  • A single timestep (no dynamics) or the dynamics are linear

If any fails:

  • Nonlinear HHH → ThreeDVar (chapter 5)

  • Dynamics → StrongFourDVar / IncrementalFourDVar (chapters 6, 8)

  • Non-Gaussian likelihood → AmortizedPosterior with score head (chapter 10)

  • Multimodal posterior → ensemble methods via filterax

OptimalInterpolation does not check that obs_op is linear: it linearises a nonlinear operator at xbx_bxb​ and returns a single extended-Kalman update, so a nonlinear HHH belongs in ThreeDVar.
