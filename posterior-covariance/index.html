Posterior Covariance

A MAP estimate x∗x^*x∗ is the start of the answer, not the end. Real DA needs a posterior (mean, covariance and provenance) for downstream consumers (population models, decision pipelines, alerting systems) to propagate uncertainty correctly. This chapter covers the four posterior-covariance computations vardax supports and when to use which; the method chapters point here for that choice.

The Posterior container¶

Every analysis emits a Posterior(mean, cov, samples, provenance), plus the pieces of a linear control when it has one:

The covariance is an AbstractLinearOperator and is never materialised. The mat-vec P∗vP^* vP∗v and the diagonal diag(P∗)\mathrm{diag}(P^*)diag(P∗) are computed on demand without building the dense P∗P^*P∗.

posterior.sample(key, n_samples) draws x(e)=x∗+(P∗)1/2ξ(e)x^{(e)} = x^* + (P^*)^{1/2} \xi^{(e)}x(e)=x∗+(P∗)1/2ξ(e) with ξ(e)∼N(0,I)\xi^{(e)} \sim \mathcal{N}(0, I)ξ(e)∼N(0,I). The square root comes from gaussx.sqrt, which is closed form for structured operators and a dense eigendecomposition otherwise. When the posterior came from a linear control (a LinearParameterization, ReducedBasisFourDVar(basis=...) or IncrementalFourDVar’s whitened control), it draws in coefficient space instead, x(e)=x∗+ΦPθ1/2ξ(e)x^{(e)} = x^* + \Phi P_\theta^{1/2} \xi^{(e)}x(e)=x∗+ΦPθ1/2​ξ(e), which only factors the small PθP_\thetaPθ​. A posterior that already holds samples returns a random subset of them.

OptimalInterpolation and IncrementalFourDVar produce posteriors as part of the analysis call (closed-form / GN-Hessian reuse). The other five methods pair with an explicit PosteriorAdapter.

Four posterior families¶

1. Closed form (BLUE / OI)¶

For OptimalInterpolation, the posterior is exact: P∗P^*P∗ is the BLUE covariance (4.5).

posterior(batch) takes one window and returns the exact BLUE covariance in its observation-space form, P∗=B−BH⊤(HBH⊤+R)−1HBP^* = B - B H^\top (H B H^\top + R)^{-1} H BP∗=B−BH⊤(HBH⊤+R)−1HB. The cov operator is lazy: each mat-vec solves the innovation system the analysis solved, with the same solver, and never applies B−1B^{-1}B−1, so a smooth BBB that CG cannot invert is no obstacle. This is the cheapest and most accurate posterior, when it applies.

2. Laplace approximation¶

For ThreeDVar and the 4DVar models, we approximate the posterior at the MAP as a Gaussian whose covariance is the inverse Hessian of the cost, and drop the second-derivative term of the observation misfit (the Gauss-Newton approximation). What the observations depend on decides the precision.

A single analysis time (ThreeDVar) gives

PLaplace∗=(∇2J(x∗))−1≈(B−1+H′(x∗)⊤R−1H′(x∗))−1P^*_\text{Laplace} = \left(\nabla^2 J(x^*)\right)^{-1} \approx \left(B^{-1} + H'(x^*)^\top R^{-1} H'(x^*)\right)^{-1}PLaplace∗​=(∇2J(x∗))−1≈(B−1+H′(x∗)⊤R−1H′(x∗))−1
(13.1)

where JJJ is the 3DVar cost (5.1) and H′(x∗)H'(x^*)H′(x∗) the Jacobian of the observation operator at the MAP, so the bracket is the Gauss-Newton Hessian (5.3) evaluated at x∗x^*x∗.

In a 4DVar window (StrongFourDVar, IncrementalFourDVar, ReducedBasisFourDVar without a basis), the observations at time ttt depend on x0x_0x0​ through the model, so the covariance is the inverse of the Gauss-Newton Hessian (8.4):

PGN∗=HGN−1P^*_\text{GN} = \mathbf{H}_\text{GN}^{-1}PGN∗​=HGN−1​
(13.2)

where HGN\mathbf{H}_\text{GN}HGN​ is evaluated along the analysis trajectory, Mt′M'_tMt′​ is the tangent-linear model from x0x_0x0​ to time ttt and Ht′H'_tHt′​ includes the mask mtm_tmt​. Never-observed state components that the dynamics couple to observed ones are constrained through Mt′M'_tMt′​, so their posterior variance drops below the prior even though no observation touches them.

For WeakFourDVar, the control is (x0,η1,…,ηT)(x_0, \eta_1, \ldots, \eta_T)(x0​,η1​,…,ηT​) of the weak-constraint cost (7.2), and the precision gains Qt−1Q_t^{-1}Qt−1​ on each ηt\eta_tηt​. The adapter returns the x0x_0x0​ block of the inverse, which is the Kalman-smoother covariance of x0x_0x0​ in the linear-Gaussian case. Pass analysis=(x0, eta).

It prints 0.17 0.13 0.15 0.38 0.85 1.00. Cells 3 and 4 are never observed, but the ring average carries them into observed cells within the window, so their variance drops below the prior’s 1; cell 5 would need a third step to reach an observed cell and keeps the prior variance.

The adapter reads the model’s obs_op and rollout (an .as_analysis_step() wrapper works too) and the window’s length and mask from batch, which must hold a single window. It returns cov as an AbstractLinearOperator: each mat-vec is a Krylov solve (lineax.CG by default, solver= to change it), and each Krylov iteration is one tangent-linear plus one adjoint pass through the rollout. Nothing is materialised.

A linear control, parameterization=LinearParameterization(basis, x_b) or ReducedBasisFourDVar(basis=...), has x=xb+Φθx = x_b + \Phi\thetax=xb​+Φθ and the penalty 12θ⊤Q−1θ\frac{1}{2} \theta^\top Q^{-1} \theta21​θ⊤Q−1θ in place of BBB (the reduced-basis cost (23.5), whose coefficients chapter 23 calls uuu). The adapters then build the precision in coefficient space and map it to the state:

Pθ=(Q−1+Φ⊤G′⊤R−1G′Φ)−1, and Px=ΦPθΦ⊤P_\theta = \left(Q^{-1} + \Phi^\top G'^\top R^{-1} G' \Phi\right)^{-1}, \text{ and } P_x = \Phi P_\theta \Phi^\topPθ​=(Q−1+Φ⊤G′⊤R−1G′Φ)−1, and Px​=ΦPθ​Φ⊤
(13.3)

where Φ\PhiΦ is the basis, QQQ the prior covariance of the coefficients θ\thetaθ, and G′G'G′ the single-time H′H'H′ or the strong-constraint window map Ht′Mt′H'_t M'_tHt′​Mt′​ stacked over ttt. The whitened control Φ=L\Phi = LΦ=L, Q=IQ = IQ=I with B=LL⊤B = LL^\topB=LL⊤ gives exactly the state-space posterior. Any other parameterization (a NeuralFieldParameterization, say) and a parameterized WeakFourDVar raise ValueError: their prior is not BBB, and their decode is not affine.

Gaussian-likelihood only. For non-Gaussian likelihoods (heavy tails, censored, count data), the Laplace approximation is wrong; use ensemble or amortized posteriors.

Unimodal-around-MAP only. If the posterior is multimodal, the Laplace approximation captures only the local mode. Diagnose by running multiple MAPs from perturbed starting points.

4. Ensemble (filterax bridge)¶

For multimodal posteriors, non-Gaussian likelihoods, or hybrid EnVar (Epic 9), build the posterior from an ensemble of analyses:

Pens∗=1M−1∑m=1M(x(m)−xˉ)(x(m)−xˉ)⊤P^*_\text{ens} = \frac{1}{M - 1} \sum_{m=1}^{M} (x^{(m)} - \bar{x})(x^{(m)} - \bar{x})^\topPens∗​=M−11​m=1∑M​(x(m)−xˉ)(x(m)−xˉ)⊤
(13.4)

where each member x(m)x^{(m)}x(m) is a separate vardax analysis with a perturbed initial condition or observation realisation, MMM is the number of members and xˉ\bar{x}xˉ their mean.

Here the M=8M = 8M=8 members re-run the strong 4DVar above on perturbed observations y(m)=y+σε(m)y^{(m)} = y + \sigma \varepsilon^{(m)}y(m)=y+σε(m), and λ=1.1\lambda = 1.1λ=1.1 inflates the sample covariance (13.4). Inflation is built in. Localisation is not: without it, the sample covariance from M≪NM \ll NM≪N members is rank-deficient and noisy, so taper it (for example with filterax’s localisation) before using it for anything spatial.

Export with GaussianMarkLikelihood¶

Per-event posteriors feed downstream population models (TMTPP, hierarchical Bayesian) via a serialisable mark-likelihood:

It prints ['cov_diag', 'event_metadata', 'mean', 'provenance', 'samples']. vardax ships no catalog writer; the JSON text goes to whatever store the population layer reads.

The serialised form is consumed by Tier V population models without re-running vardax. Decision D10 makes this contract explicit, since it is how the inference layer hands off to the population layer.

Validation gates¶

Posteriors are only as good as they agree with reality, so the six-step cycle checks a fast posterior against its oracle with the posterior-agreement gate (14.4), the Jacobian gate (14.3) and simulation-based calibration; chapter 14 states the gates and the functions that implement them.
