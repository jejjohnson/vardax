Observation Model

The observation operator H:Rn→RmH : \mathbb{R}^n \to \mathbb{R}^mH:Rn→Rm maps the state xxx to predicted observations y^=H(x)\hat{y} = H(x)y^​=H(x). Real instruments rarely measure the state directly; they smooth, average, mask or project it. Getting HHH right is what separates an inversion that recovers the truth from one that returns a biased fantasy.

The likelihood model¶

vardax assumes Gaussian observation errors,

y=H(x)+ε, with ε∼N(0,R)y = H(x) + \varepsilon, \text{ with } \varepsilon \sim \mathcal{N}(0, R)y=H(x)+ε, with ε∼N(0,R)
(2.1)

where y∈Rmy \in \mathbb{R}^my∈Rm are the observations and RRR is the observation-error covariance, so p(y∣x)=N(y;H(x),R)p(y \mid x) = \mathcal{N}(y; H(x), R)p(y∣x)=N(y;H(x),R). The observation cost in the variational problem is the negative log-likelihood up to a constant,

Jobs(x)=12∥y−H(x)∥R−12=12(y−H(x))⊤R−1(y−H(x))J_\text{obs}(x) = \frac{1}{2} \|y - H(x)\|^2_{R^{-1}} = \frac{1}{2} (y - H(x))^\top R^{-1} (y - H(x))Jobs​(x)=21​∥y−H(x)∥R−12​=21​(y−H(x))⊤R−1(y−H(x))
(2.2)

Non-Gaussian likelihoods (Student-ttt, censored, count data) require either a non-Gaussian extension of JobsJ_\text{obs}Jobs​ or amortized inference with a flow / score-based head (chapter 10).

The ObservationOperator protocol¶

Every vardax observation operator satisfies pipekit_cycle.ObservationOperator, restated here with typed signatures:

The linearize() method returns a lineax.AbstractLinearOperator (typically JacobianLinearOperator via autodiff, but structured overrides are common). The transpose / adjoint comes for free from lineax.

This contract is the same regardless of whether the operator is a masked identity, an averaging kernel, or a multi-instrument fusion.

Five operator families¶

Masked identity¶

In the simplest case we observe the state where the mask is non-zero,

H(x)=m⊙x, with m∈{0,1}nH(x) = m \odot x, \text{ with } m \in \{0, 1\}^nH(x)=m⊙x, with m∈{0,1}n
(2.3)

where ⊙\odot⊙ is the element-wise product.

Tangent-linear: H′(x)=diag(m)H'(x) = \mathrm{diag}(m)H′(x)=diag(m). Use case: SSH altimetry along-track gaps, SST with cloud masks, in-situ samples on a grid.

The mask is passed per call, so the models apply it to H′H'H′ themselves. The examples on this page build on each other, starting from a toy state on N=6N = 6N=6 cells.

Linear projection¶

A pre-computed projection from state to observation space is

H(x)=Hmat⋅xH(x) = H_\text{mat} \cdot xH(x)=Hmat​⋅x
(2.4)

where Hmat∈Rm×nH_\text{mat} \in \mathbb{R}^{m \times n}Hmat​∈Rm×n is a fixed matrix.

Use case: Lagrangian footprint matrix from a particle simulator (observation at receptor = footprint-weighted source field), spectral filtering, spatial interpolation. The matrix is stored as an AbstractLinearOperator so structure (sparse, low-rank, Kronecker) can be exploited.

Here the footprint F=HmatF = H_\text{mat}F=Hmat​ maps the six cells to M=3M = 3M=3 receptors, each averaging two neighbouring cells.

Averaging kernel: RTM L2 products¶

For satellite L2 products derived from optimal-estimation retrievals (TROPOMI CH₄, EMIT CH₄, OCO CO₂, MOPITT CO, …), the L2 retrieval is not a direct sample of the mixing-ratio profile xxx. The retrieval applies a smoothing matrix AAA (the averaging kernel) and falls back to a retrieval prior xax_axa​ where the signal is weak:

y^=A(h⊙x+(1−h)⊙xa)\hat{y} = A (h \odot x + (1 - h) \odot x_a)y^​=A(h⊙x+(1−h)⊙xa​)
(2.5)

where the symbols are

SymbolDescription
x∈RNx \in \mathbb{R}^Nx∈RNModel state (profile, surface field)
xa∈RNx_a \in \mathbb{R}^Nxa​∈RNRetrieval prior from L2 metadata
h∈RNh \in \mathbb{R}^Nh∈RNWeighting vector (often pressure-weighted)
A∈RN×NA \in \mathbb{R}^{N \times N}A∈RN×NAveraging kernel matrix

Tangent-linear: H′(x)=A⋅diag(h)H'(x) = A \cdot \mathrm{diag}(h)H′(x)=A⋅diag(h).

Skipping the averaging kernel is the most common cause of bias in operational satellite inversions. Treating an L2 retrieval as a direct measurement of the truth gives systematically wrong posteriors, especially when the retrieval prior xax_axa​ differs from the inversion prior xbx_bxb​. vardax exposes AveragingKernel as a first-class operator because this is a day-one requirement, not a future feature.

The toy kernel AAA below is tridiagonal, the prior xax_axa​ is flat and the sensitivity hhh falls from 1 to 0.2 with height. The check of the tangent linear against Adiag(h)A \mathrm{diag}(h)Adiag(h) formed densely prints True.

When AAA has structure (Kronecker for separable kernels, low-rank for under-determined inversions, banded for compactly-supported kernels), store it as a gaussx.AbstractLinearOperator. The tangent linear A⋅diag(h)A \cdot \mathrm{diag}(h)A⋅diag(h) is then computed without ever materialising the dense AAA.

Multi-instrument fusion¶

Operational satellite work combines multiple instruments. Each instrument has its own HiH_iHi​, mask mim_imi​, error covariance RiR_iRi​ and optionally an averaging kernel (Ai,xa,i,hi)(A_i, x_{a,i}, h_i)(Ai​,xa,i​,hi​). The fused observation cost composes (2.2) at the likelihood level,

Jobs(x)=∑i∈Iαi⋅12∥mi⊙(yi−Hi(x))∥Ri−12J_\text{obs}(x) = \sum_{i \in \mathcal{I}} \alpha_i \cdot \frac{1}{2} \|m_i \odot (y_i - H_i(x))\|^2_{R_i^{-1}}Jobs​(x)=i∈I∑​αi​⋅21​∥mi​⊙(yi​−Hi​(x))∥Ri−1​2​
(2.6)

where I\mathcal{I}I is the set of instruments and αi\alpha_iαi​ is a per-instrument weight. The weight defaults to uniform; tuning it is for hierarchical bias correction (Epic 9). Each InstrumentSpec carries its own operator, mask and RiR_iRi​. Quality masks zero-weight unreliable pixels, so they contribute zero log-likelihood rather than being dropped, which lets us audit the effective per-instrument observation count.

Tangent-linear and adjoint contract¶

For incremental 4DVar (chapter 8), every observation operator must expose linearize, whose operator applies H′H'H′ with mv and H′⊤H'^\topH′⊤ with transpose().mv. The pair must pass the adjoint test

⟨H′u,v⟩=⟨u,(H′)⊤v⟩ for all u,v\langle H' u, v \rangle = \langle u, (H')^\top v \rangle \text{ for all } u, v⟨H′u,v⟩=⟨u,(H′)⊤v⟩ for all u,v
(2.7)

up to floating-point tolerance, where uuu is a state-space vector and vvv an observation-space vector. Failing this test means the gradient flowing back through HHH is wrong, and any downstream optimiser will take wrong steps. Observation-error covariance RRR¶

RRR is supplied as a lineax.AbstractLinearOperator. Common parameterisations:

  • Diagonal: lineax.DiagonalLinearOperator(variances). The default for heteroscedastic retrievals (per-pixel σ from L2 metadata).

  • Block-diagonal: gaussx.BlockDiag(*instrument_covs). Per-instrument diagonals when fusing.

  • Structured: kernellib.ImplicitKernelOperator(matern, coords) if observation errors are spatially correlated (rare, but it matters for high-resolution imaging spectrometers).

The models’ solves reject gaussx operators until they are wrapped as a lx.FunctionLinearOperator, as chapter 4 does for BBB.

The choice flows into (2.2) via R−1R^{-1}R−1, which is applied lazily: the inverse is never materialised, only applied to vectors via lineax.CG.

When the observation model is wrong¶

A common failure mode: HHH is misspecified (wrong averaging kernel, missing instrument bias, ignored representation error). The MAP x∗x^*x∗ then converges to a wrong answer with a confident-looking posterior. Diagnostics:

  • Innovation statistics d=y−H(xb)d = y - H(x_b)d=y−H(xb​). Should be roughly mean-zero and consistent with diag(HBH⊤+R)\sqrt{\mathrm{diag}(H B H^\top + R)}diag(HBH⊤+R)​. Large systematic offsets indicate bias.

  • Posterior vs prior log-evidence ratio. If the data move the posterior much further than σpost\sigma_\text{post}σpost​ from the prior, the BBB or RRR assumptions are wrong.

  • Cross-instrument disagreement. Per-instrument residual statistics should be consistent; large disagreements flag uncorrected bias.

Epic 9 adds joint bias estimation for the cross-instrument case.
